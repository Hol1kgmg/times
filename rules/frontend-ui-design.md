# frontend UI デザインルール

参照: [Figma 基礎資料](https://www.figma.com/design/KIz51olPtwpG8lU3xObA8s/times?node-id=12-4)
値の正は `frontend/src/app/styles/global.css` のトークン。ここには値を書かない。

トップページ (`/`) の見た目をアプリ全体の型とする。ほかの画面とコンポーネントは仮実装なので見本にせず、作り直すときにこのルールへ寄せる。ただしシェルの節は、本実装の前にルールとして先に決めておく。

## 原則

- 有彩色はオレンジ 2 段だけ。ロゴ色 `--color-brand` はロゴ・bot アバター・`.dev`・アイコンに、操作色 `--color-accent` (`--color-brand` の別名。白地で 2.8:1 と AA 未達は承知のうえ、adr/frontend/0003) はリンク・選択中・ステータスに使う。地に敷くのは `--color-brand-faint` だけ (例外はホットトピックの HOT の吹き出し) で、面としては強調面、行やセル (サイドバー・カレンダーの日付など) としてはホバー・選択中に `--color-selected` を通して使う。他の有彩色は使わない。例外は `--color-danger` (赤) で、送信を断られて直す必要のある箇所の枠線とエラー文にだけ使う。地には敷かない。橙はアクセントと見分けられず、エラーに気付けないため。
- 状態は枠線・背景の濃淡・小さな影・アクセント色だけで表す。グラデーション、強い影、波線などの装飾は使わない。
- 色の変化 (アクセント色・濃淡) はホバー中・押し続けている間の表現にだけ使う。ホバーの見た目は `:hover` ではなく `[data-hovered]` に付け、要素には `useHovered` / `HoverButton` / `HoverLink` で属性を出す。`:hover` も `@media (hover: hover)` もタッチ付きの PC ではタップで付いて残るので、操作ごとにタッチを除く react-aria の `useHover` で判定する (adr/frontend/0007)。
- 操作領域 (入力欄・ボタン) は角丸で区切り、本文や一覧と見た目で区別する。
- 押す対象の位置を操作の途中で動かさない。中身で高さや幅が変わる面は、いちばん大きい場合の大きさを普段から取っておく。押そうとした先がずれて押し間違えるため。
- 押せない要素は種類を問わず、文字を `--color-text-faint` にしてカーソルを `not-allowed` にする。
- 狭い画面では中身を縮め続けず、読めなくなる前に列を減らす。
- 押した先で何が出るか分からない操作は置かない。行き先が画面にあるなら、その行き先 (年表示の月の枠など) を直接押させる。
- 色・影・角丸・余白はトークンで指定する。CSS Modules に生の値を書かない。
- 余白は 4 の倍数。画面パディングとセクション間は `--space-4`、カード内は `--space-2` 〜 `--space-3`。
- 文言は話し言葉 (「〜してます」) にする。業務アプリやサービス紹介の硬さを出さないため。

## 面と部品の型

トップで決めた形を全画面で使う。

- **通常面**: `--color-bg` の地。面どうしの切り替えは色と 1px 線 (`--color-border`) だけで行う。
- **強調面**: `--color-brand-faint` の地。1 画面に 1 つまで、その画面の主役の面にだけ敷く (トップならヒーロー)。この上では `--color-text-faint` が 4.5:1 を切るので、文字は `--color-text-muted` 以上にする。
- **浮かせたカード**: `--color-surface` の地 + 境界線 + `--radius-panel` + `--shadow-raised`。主役の内容を強調面から浮かせるときに使う。帯は付けない。
- **透かして浮かせる面**: 半透明の地 `--color-surface-floating` + `--backdrop-floating` + `--shadow-floating`、境界線なし。本文の上に重なって追従する面 (モバイルヘッダー) にだけ使う。
- **枠のグリッド**: 1 つずつ境界線 + `--radius-control` の枠に入れ、幅に合わせて折り返すグリッドに並べる。枠ごと押せるときは、見出しのボタンの当たり判定を `::after` で枠全体に広げ、ホバー中は枠線を `--color-accent` にする。見出しは button の中に入れられないため。
- **ボタン**: `--color-surface-raised` の地 + 境界線 + `--radius-control` + `--shadow-menu`、文字は `.t-body` の `--color-text`。押せないときは `--color-surface` の地に戻して影を消す (文字とカーソルは原則の押せない形)。枠やカードと同じ見た目だと押せるか分からないため。
- **入力欄**: 付属するボタン (カレンダーなど) は同じ角丸の枠の中に入れ、1px 線で区切る。状態は外枠に出し、フォーカス中は `--color-accent`、断られたら `--color-danger` にする。
- **選択の型**: 選択中とホバーは同じ地 (`--color-selected`) と `--color-accent` の文字にし、選択中だけ文字を 600 にして見分ける (サイドバー、日付)。
- **選べない理由**: 見た目は小さな印 (`--color-brand` のドットなど) だけにし、理由の言葉は読み上げ用のラベルに入れる。一覧の中に説明文を並べない。ラベルを部品が作るとき (React Aria Components の `Calendar`) は、部品の「選べない」の読み上げで代える。
- **アイコン**: animate-ui の単色アイコン (`--color-brand`)。
- **モーダル**: `<dialog>` の `showModal()`。本体は浮かせたカードの型 (`global.css` の `.modal` を `composes` する)、`::backdrop` は `--backdrop-floating` でぼかすだけで暗くしない。外側のクリックでは閉じず、ボタンと Esc で閉じる。入力の途中で誤って消えないようにするため。例外は入力を持たないモーダル (日付ピッカー、プレビュー) で、外側のクリックでも閉じる (`useModal` の `closeOnOutside`)。日付ピッカーは閉じるボタンも置かない。
- **長い一覧の折りたたみ**: 内部スクロールは使わない (入れ子のスクロールは操作しづらい)。高さで切って下端をフェードさせ、展開ボタンを出す。
- **ホバー前提の補助**: ホバーで出るもの (プレビュー、その案内) を置くか、隠しておくものを最初から出すかは `@media (--hover)` で決める。出すきっかけは `[data-hovered]` (原則のホバーの見た目と同じ) で見る。`any-hover` は主な入力がタッチの端末でも一致し、静止画で出すべきものが隠れたままになるので使わない。

## 動き

画面に固有の動き (トップのフェード、HOT の吹き出し、ロゴ、モバイルヘッダー) は各節に書く。ここには全画面で共通の型だけを置く。

### 原則

- 時間は変化の大きさで 3 段に分ける: 押したときの反応 0.1s < 開閉・フェード 0.2s < 中身の入れ替え 0.3s。どれも ease-out。
- 動きで場所の関係を示す。前後への送りは向きに合わせて滑らせ (次は上へ、前は下へ)、切り替えの前後で同じものを指す要素 (数字・見出し) は消して出し直さず移動させる。
- 動く中身は自分の面の外にはみ出させず、面の中で切る。例外は面の外から来ること自体に意味がある移動だけ。
- 動いている間は操作を受けない (カーソル `not-allowed`、文字選択もさせない)。途中で押されると状態がずれるため。
- ホバーなどの一時的な状態は、動き出す前に落とす。ホバーの見た目のまま撮られると、そのまま伸び縮みするため。
- 動かす要素を絞る。view transition の名前を全部に付けると、撮るだけで固まるため。
- 消える側の動きも最後まで見せる。要素を外すのはアニメーションが終わってから。
- `prefers-reduced-motion: reduce` では transition、`:active` の拡大、view transition をすべて止める。新しく動きを足すときは同じ CSS Modules に止める指定も書く。

### 型

- **押したときの反応**: `:active` (React Aria Components の部品では `[data-pressed]`) の小さな拡大 (`transform`)。拡大率は面が大きいほど控えめにする。ブラウザ既定のタップハイライト (灰色) は `global.css` で `a, button` から一括で消す。トークン外の色で、状態の型から外れるため。
- **アイコン**: 枠や行のホバーで 1 回だけ動かす。動かし続けない。
- **開閉**: button (`aria-expanded`) + grid の `0fr` → `1fr` で高さを補間する。シェブロンは同じ時間で回す。`<details>` は閉じる側をアニメーションできないので使わない。
- **モーダル**: フェードと小さな縮小からの戻り。開閉は `shared/ui/modal` の `useModal` を通す (`onClose` はフェードアウトの後に呼ばれる)。
- **中身の入れ替え**: 同じ面の中で中身を入れ替えるとき (カレンダーの月送り、年と月の切り替え) は React の `<ViewTransition>` を使う。

## キーボード

- 並んだ選択肢 (グリッドなど) は WAI-ARIA の標準に合わせる。Tab で止まるのはグループに 1 つ (選択中、なければいちばん意味のあるもの) だけで、中は矢印キーで移る。選べないものにも矢印キーでは止まり、選べないことを読み上げる (adr/frontend/0008)。
- 状態と振る舞いを持つ部品は、React Aria Components にある部品なら自前で書かずにそれを使う。状態の見た目は部品が付ける `[data-hovered]` / `[data-pressed]` / `[data-selected]` / `[data-unavailable]` などに付ける (adr/frontend/0008)。
- モーダルや一覧を開いたときは、選択中の要素 (なければいちばん意味のある要素) にフォーカスする。先頭のボタンに置いたままにしない。

## タイポグラフィ

フォントは Klee One (body で指定済み)。用途別に `global.css` のクラスを使う。CSS Modules からは `composes: t-title from global;` で取り込む。

記事タイトル・プレビュー・入力欄など、データ由来の文字を出す要素には `font-family: var(--font-dynamic);` を付ける。body の既定はトップとシェルのソース中の固定文字だけを含むサブセットで、それ以外の字は端末のフォントになる (adr/frontend/0005)。トップ以外の画面は、ページの一番外側に `font-family: var(--font-dynamic);` を付ける。

| 用途 | クラス | サイズ / ウェイト |
|---|---|---|
| 日付見出し | `.t-date` | 18px / 600 |
| カテゴリ見出し | `.t-label` | 14px / 600 |
| 記事タイトル | `.t-title` | 16px / 400 / line-height 24px |
| カード本文 | `.t-body` | 13px / 400 / line-height 1.5 |
| メタ (ドメイン・時刻) | `.t-meta` | 11px |

複数ページで同じ複合ブロック (見出し + メタなど) が出るまで React コンポーネントには昇格させない。

## ロゴ

- `docs/logo.svg` が元データで、`shared/ui/logo.tsx` はその写し (オレンジのタイル + 白 `Z` + 黄ドット + Arial Rounded のワードマーク `z_times.dev`)。コンセプトと要件は adr/frontend/0004。
- 元 SVG のアニメーション (文字の傾き、`.dev` の落下、ベル、ドット) はサイドバーの `variant="hover"` でだけ再生する。普段はアイコンだけで、アイコンのホバー中に文字をフェードインさせる。ホバーできない環境 (タッチ) では記事プレビューと同じくホバー前提の補助として扱い、アニメーションを付けず文字まで静止画で出す。
- トップの h1 (`variant="hero"`) は静止画。favicon は `public/favicon.svg` (アイコン部分のみ)。

## ダークモード

- `prefers-color-scheme: dark` で `global.css` のトークンの値だけを差し替える。CSS Modules で色を分岐しない。
- 地は真っ黒にせず、グレー寄りの 3 段を重ねる: 地・強調面 `--color-bg` < 帯 `--color-fill-faint` < カード `--color-surface`。黒に近いと面の差が消えて 1 枚に見えるため。
- `--color-text-faint` は、文字を置く面でいちばん明るい `--color-surface` の上で 4.5:1 を満たす値にする。`--color-fill-subtle` はそれより明るく 4.5:1 を切るので、faint の文字を置かない。
- 強調面は地と同じ色にし (`--color-brand-faint` を `--color-bg` の別名にする)、1px 線だけで区切る。暗い地で橙を薄めると泥色になり、グレーを敷くとカードが沈むため。
- サイドバーは帯と同じ `--color-fill-faint` の地にし、ライトと同じく右端の 1px 線で区切る。ホバー・選択中の地 `--color-selected` は `--color-fill-subtle` の別名にする (ライトでは `--color-brand-faint`)。`--color-brand-faint` (= `--color-bg`) はサイドバーやカードの地より暗く、選択中が沈むため。
- 押せるボタンの地 `--color-surface-raised` は `--color-fill-subtle` の別名にする (ライトでは `--color-surface`)。暗い地では影がほぼ見えず、カードと見分けられないため。押せないボタンは faint の文字を置くので `--color-surface` に戻す。

## 画面ごとの決まり

### トップページ (入り口)

- `/` もシェル (サイドバー) の中に置く。「何のアプリか」はヒーローの説明文で伝える (adr/frontend/0003)。モバイルヘッダー以外のヘッダーは置かない。
- 構成は 3 つの面。ヒーロー (強調面、中央寄せ: ロゴ (`<Logo hero />`) + 説明 1 文 + 投稿ブロック + 使い方のヒント 1 行) → 「ゆるい説明」(通常面: リード + カテゴリ一覧 + 気になりそうなこと) → フッター (通常面: ロゴ)。運営者の GitHub は FAQ の「誰がやってる？」にだけ置く。
- 「何のサイトか」はヒーローの説明文だけに書く。リードはセクションの案内、FAQ はヒーローで言っていないこと (見方・過去分・更新頻度・運営者) に答え、定義を繰り返さない。
- 投稿ブロックは浮かせたカード。上端に日付ピルと件数 (`.t-meta` の muted)、その下に投稿。更新は不定期なので「毎日」など頻度を言い切る文言は出さない。チャンネル名 (`#…`) は出さない。
- 表示は最新の 1 日分だけ。
- カテゴリ一覧は枠のグリッド + アイコン。よくある質問は開閉の型で、最初の 1 問だけ開いておく。
- 投稿ブロックは 1 画面に収まる高さで折りたたみ、収まらない日だけフェードと「すべて表示」ボタンを出す。展開後に折りたたみ直すボタンは置かない。
- 折りたたみ時はヒーローごと窓の高さに収める (PC・タッチ共通)。下限は `.fit` で 320px (スマホ横向きでも記事が数行見える高さ)。プレビューは画面基準で上下を反転し、カードの外にはみ出してよい。モバイルと高さ 480px 以下 (スマホ横向き) はヒーローの上下余白を `--space-4` に詰める。
- フェードは高さを測る前 (SSR) から出し、フェードにかかる記事リンクはポインター操作を受けない。展開ボタンだけ計測後にアニメーションで出す。
- 過去 Digest への導線はサイドバーに置き、投稿ブロックの中には置かない。

### Digest の投稿

- Slack のチャンネルの構造を借りる: 日付区切り + カテゴリごとの bot の投稿。色は Slack を真似ない。トップ・タイムライン・編集のプレビューで同じ形にする (`shared/ui/digest-post`)。
- 日付は線の中央にピル (`.t-label` + 境界線 + 角丸 9999px)。日付は `10月20日(火)` の形で出す。
- 1 日分が 1 投稿。左にアバター (36px、`/favicon.svg`)、右に `z_times.dev` とカテゴリごとの小見出し + 記事行。投稿時刻は出さない。モバイルではアバターと `z_times.dev` を 1 行目に並べ、カテゴリと記事行は左端から全幅で出す (記事行のインデントもなくす)。
- 記事行は favicon を行頭マーカーにする。箇条書きの記号は付けない。子記事は左 1px 線でインデント。
- ホットトピックはカテゴリではなく記事の印 (specs/004)。専用の区画は作らず、本来のカテゴリの中で示す。カテゴリの見通しを崩さないため。
- ホットトピックの親の記事行は、タイトルの後ろに炎のアイコン (`--color-brand`) を付ける。ホバー・フォーカス中は炎を揺らし、炎の横から「HOT」の吹き出しを `scale` (行き過ぎて戻す easing、0.2s) で飛び出させ、しっぽの先を軸に上から下へ 1 回だけ下ろす。吹き出しは animate-ui のアイコンと同じ作りの SVG (`icons/hot-bubble.tsx`: 左側面からしっぽが生えた角丸の四角を `--color-brand` で塗り、中に `--color-on-brand` の太字で HOT)。地に橙を敷く唯一の例外で、ロゴのタイルと同じ「橙の地に白」の小さな印として扱う。白文字は 2.8:1 と AA 未達だが、ホバー中の補助で意味は炎とリンク名でも伝わるので許容する。幅は普段から確保し、ホバーで折り返しを変えない。タッチ端末ではロゴと同じく動きなしで最初から吹き出しまで出す。子記事には付けない。
- 記事タイトルのリンクは普段 `--color-text` で下線を付けず、ホバーとフォーカス時だけ `--color-accent` にする。記事が並ぶ面でオレンジが散らばらないようにするため。行全体がリンクで、行頭の favicon が目印になるので下線は不要。
- 記事カード (OG プレビュー) はホバー時だけ出す。常時表示はしない。

### 日付ピッカー (Digest の登録・編集)

- 日付欄は `<input type="date">` に入力欄の型でカレンダーボタンを付け、ブラウザ既定のピッカーのボタンは隠す。2 つ並ぶため。ピッカーは日付を選ぶと閉じる。
- 月表示は React Aria Components の `Calendar` で作り、年表示と、その切り替えの動きは自前で持つ。外枠はモーダルの型の `<dialog>` のままにする (adr/frontend/0008)。
- 登録済みの日付は選べない理由の型 (数字の下に `--color-brand` のドット、`isDateUnavailable`) で示す。編集中の Digest 自身の日付は、そのまま保存できるので選べるままにする。

### シェル (サイドバー・モバイルヘッダー)

- サイドバーはチャンネル一覧。通常面と同じ地 (`--color-sidebar-bg`) にし、右端の `--color-border` の 1px 線でメインと区切る。暗い面を置かず明るい印象を保つため。ホバーと選択中は同じ薄い地にし、選択中だけ文字を 600 にして `#` をアクセント色にする。地をオレンジで塗りつぶすと一覧の中で強すぎるため。`#` の色だけでは薄い地の上で 3:1 を切り、ホバー中の行と見分けられないので太さでも示す。
- サイドバーとモバイルヘッダーは全員に出す。タブはログイン状態で出し分け、未ログインには閲覧用のチャンネル (`#general`) だけを出す。管理者向けのタブ (記事を登録・記事を編集・ログアウト) はログイン中だけ。
- 狭い画面 (`--narrow`。端末の種類ではなく幅で判定し、PC でも同じに振る舞う) ではサイドバーを出さず、ヘッダーがそのまま下へ伸びてチャンネル一覧のメニューになる。ヘッダーのバーはアイコンを載せず、全体を 1 つの開閉ボタンにする。開いている間だけ左端に × (`--color-text-muted`、飾り) をフェードで出す (開閉の型、閉じた形はピル、開いた形は `--radius-panel`)。後ろの本文は `--backdrop-floating` でぼかし、暗くしない (状態は濃淡と線で表し、黒い幕を敷かないため)。ヘッダーはぼかしの上に置く。
