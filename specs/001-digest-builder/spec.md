# Feature Specification: 記事登録 (Digest 作成) 画面

**Feature Branch**: `001-digest-builder`

**Created**: 2026-09-22 (2026-10-25 改訂: 2 カラムとドラッグでの分類、関連記事・ホット、実登録と認証を前提に書き直し)

**Status**: Draft

**Input**: User description: times の 1 件分の Digest を管理画面上で組み立てる機能。左に URL の入力と未分類の箱、右に固定 6 カテゴリの箱を並べ、候補をドラッグで振り分けて登録する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 記事を集める (Priority: P1)

管理者は気になった記事の URL を 1 件ずつ貼り付けて実行する。システムはその URL から記事タイトルを自動で取得し、候補として「未分類」の箱に追加する。管理者はタイトルを手入力せず、入力欄以外を操作せずに、次々と URL を貼り付けて候補を溜めていける。分類や順序はこの時点では考えない。

**Why this priority**: 手作業で最も手間がかかるのがタイトルの転記である。URL からの自動取得だけでも作業量が大きく減り、単体で価値がある。後続の Story はこの候補がなければ成立しない。

**Independent Test**: URL を 3 件連続で貼り付け、未分類の箱に 3 件の候補がタイトル・ドメイン・サイトのアイコン付きで並ぶことを確認できる。

**Acceptance Scenarios**:

1. **Given** 候補が 1 件もない状態, **When** 記事の URL を貼り付けて実行する, **Then** その記事のタイトルが入った候補が 1 件、未分類の箱に追加される
2. **Given** URL を 1 件投入し終えた直後, **When** 次の URL を貼り付けようとする, **Then** 入力欄は空で、追加の操作なしにそのまま貼り付けられる
3. **Given** タイトルの取得を待っている状態, **When** 画面を見る, **Then** 処理中であることが分かり、続けて実行することができない
4. **Given** URL として成立しない文字列 (空文字、`http` / `https` 以外), **When** 実行する, **Then** 候補は追加されず、有効な URL の入力を促す表示がその場に出る
5. **Given** 同じ URL を既に投入済みの状態 (関連記事として入れたものを含む), **When** もう一度同じ URL を投入する, **Then** 重複である旨が表示され、候補は二重に追加されない
6. **Given** タイトルを取得できない記事の URL (到達不能、タイトルのないページ、HTML 以外), **When** 実行する, **Then** 候補自体は追加されたうえで、タイトルを手で入れる必要があることが示される

---

### User Story 2 - 記事をカテゴリへ振り分けて並べる (Priority: P2)

管理者は未分類の箱に溜まった候補を、右に並ぶ固定 6 カテゴリの箱へドラッグして振り分ける。カテゴリ間の移動、未分類への戻し、箱の中での並び替えも同じドラッグ 1 回で行う。マウスを使わない場合も、キーボードやタッチで同じ操作ができる。各箱の見出しには件数が出るので、未分類の残りと各カテゴリの件数が画面を見るだけで分かる。

**Why this priority**: 「集める」と「整える」を分けることが UI 設計の出発点であり、Digest の構成を決めるのはこの段階である。候補がなければ整えるものがないため P1 の後に置く。

**Independent Test**: 候補が数件ある状態で、未分類からカテゴリへ、カテゴリから別のカテゴリへ、カテゴリから未分類へ、箱の中での並び替えをそれぞれドラッグで行い、配置と件数が即時に変わることを確認できる。同じ操作をキーボードだけで行える。

**Acceptance Scenarios**:

1. **Given** 未分類の候補, **When** あるカテゴリの箱へドラッグする, **Then** その候補はそのカテゴリの箱に、落とした位置で並ぶ
2. **Given** あるカテゴリにある候補, **When** 別のカテゴリの箱へドラッグする, **Then** 未分類を経由せず 1 回で移る
3. **Given** あるカテゴリにある候補, **When** 未分類の箱へドラッグする, **Then** その候補は未分類に戻る
4. **Given** 同じ箱に複数の候補がある状態, **When** その中で順序を入れ替える, **Then** 表示順だけが変わり、箱は変わらない
5. **Given** ドラッグ中, **When** 画面を見る, **Then** どの候補を動かしているか、どこに落ちるかが分かる
6. **Given** 分類作業中, **When** 画面を見る, **Then** 未分類の残数と各カテゴリの件数が、0 件の箱も含めて同時に分かる
7. **Given** 候補が多く画面に収まらない状態, **When** 箱の見出しで閉じる操作をする, **Then** その箱の候補が畳まれ、見出しと件数だけが残る。もう一度操作すると開く
8. **Given** マウスを使えない状態, **When** キーボードで候補を選んで移動する, **Then** ドラッグと同じ移動・並び替えが行える

---

### User Story 3 - 候補を手直しする (Priority: P2)

管理者は候補ごとのメニューから、タイトルと URL の訂正、ホットの印の付け外し、取得直後の状態への戻し、削除を行う。訂正は途中でやめられ、その場合は元の内容が保たれる。何度も手を入れておかしくなった候補は、1 回の操作で取得直後の状態 (タイトル・URL) に戻せる。

**Why this priority**: 自動取得の失敗を補う手段であり、タイトルを取れなかった候補を登録できる状態にするために必要。ただし多くの候補は手直し不要なので、Story 1 と同時である必要はない。

**Independent Test**: 候補のタイトルを訂正して確定し、別の候補で訂正を中断し、別の候補を取得直後に戻し、ホットの印を付け、1 件を削除して、それぞれ期待どおりになることを確認できる。

**Acceptance Scenarios**:

1. **Given** タイトルが実際と違う候補, **When** メニューから訂正して確定する, **Then** 訂正後の内容がその場に反映される
2. **Given** 訂正の途中, **When** 確定せずにやめる, **Then** 候補は訂正前のまま変化しない
3. **Given** タイトルを取得できなかった候補, **When** タイトルを手で入力して確定する, **Then** その候補は登録できる状態になる
4. **Given** URL を訂正した候補, **When** 一覧を見る, **Then** その候補は同じ 1 件として扱われ続け、箱と位置は保たれる
5. **Given** 何度も手を入れた候補, **When** 取得直後の状態へ戻す, **Then** タイトル・URL がまとめて取得直後の値に戻り、箱と位置とホットの印は変わらない
6. **Given** 任意の候補, **When** ホットの印を付ける, **Then** その候補に印が付いたことが見て分かり、もう一度操作すると外れる
7. **Given** 任意の候補, **When** 削除する, **Then** 候補は消え、他の候補の箱と順序は保たれる

---

### User Story 4 - 関連記事をまとめる (Priority: P3)

ある記事の続報や補足の記事を、その記事の「関連記事」として下にぶら下げる。管理者は候補のメニューから「関連記事にする」を選び、すぐ上の記事の関連記事にする。関連記事は親の記事と一緒に動き、単独ではドラッグしない。関連記事どうしの順序の入れ替えと、関連記事から外す操作もメニューで行う。

**Why this priority**: 関連記事のない Digest でも登録できるため、分類と登録の流れが揃ってから足せばよい。

**Independent Test**: 候補 A の直後にある候補 B を A の関連記事にし、A を別のカテゴリへドラッグして B が一緒に移ることを確認する。続けて B を外し、A の直後に通常の候補として戻ることを確認する。

**Acceptance Scenarios**:

1. **Given** 同じ箱の中で記事 A のすぐ下にある候補 B, **When** B のメニューから関連記事にする, **Then** B は A の関連記事としてインデントされて A の下に並ぶ
2. **Given** 関連記事を持つ記事, **When** その記事を別の箱へドラッグする, **Then** 関連記事も同じ順序のまま一緒に移る
3. **Given** 関連記事, **When** 画面を見る, **Then** 関連記事だけを掴んで動かすことはできない
4. **Given** 関連記事が複数ある記事, **When** 関連記事のメニューから上下を入れ替える, **Then** 関連記事の順序だけが変わる
5. **Given** 関連記事, **When** メニューから関連記事を外す, **Then** 親の記事の直後に、同じ箱の通常の候補として並ぶ
6. **Given** 箱の先頭の候補、自分が関連記事を持つ候補、関連記事が上限に達した記事の直下の候補, **When** メニューを開く, **Then** 「関連記事にする」は選べない

---

### User Story 5 - Digest として登録する (Priority: P2)

管理者は整え終わった候補一式を、日付をつけて Digest 1 件分として登録する。日付は画面を開いた時点で当日が入っており、必要なら変えられる。未分類の候補やタイトルが空の候補が残っていれば登録できない。登録できたらトップ画面へ移り、出来上がった Digest をそのまま確かめられる。

**Why this priority**: 登録できて初めて手作業のデータ作成を置き換えられる。Story 2 と同じ優先度だが、Story 1 の候補を手で分類した状態でも登録の流れは検証できるため独立して実装できる。

**Independent Test**: 全候補を分類した状態で登録し、トップ画面に移って、カテゴリ・順序・ホットの印・関連記事が登録前の配置どおりに表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 画面を開いた直後, **When** 日付を見る, **Then** 当日が入っており、そのまま登録できる
2. **Given** 過去の日付で Digest を作りたい, **When** 日付を変える, **Then** 候補には影響せず、登録時に Digest 全体へその日付が付く
3. **Given** 未分類の候補が残っている状態, **When** 登録しようとする, **Then** 登録できず、分類が済んでいないことが分かる
4. **Given** タイトルが空の候補 (関連記事を含む) がある状態, **When** 登録しようとする, **Then** 登録できず、どの候補のタイトルが空かが分かる
5. **Given** URL の追加の途中 (タイトルの取得と翻訳を待っている状態), **When** 登録しようとする, **Then** 追加が終わるまで登録できない
6. **Given** カテゴリに候補が 1 件もない状態, **When** 画面を見る, **Then** 登録は実行できない
7. **Given** すべての候補の分類が済んだ状態, **When** 登録を実行する, **Then** 全候補が同じ日付の Digest 1 件分として、カテゴリの固定順・箱内の順・関連記事の順で送られ、トップ画面へ移る
8. **Given** 登録に失敗した, **When** 結果を見る, **Then** 候補は 1 件も失われず、何を直せばよいかが分かり、そのまま登録し直せる

---

### Edge Cases

- 同じ URL を末尾スラッシュや `#fragment` 違いで入力した場合、別の候補として扱う (正規化は行わない。重複判定は完全一致)。
- タイトル取得に時間がかかる場合 (目安 5 秒超) は取得を打ち切り、タイトル空の候補として追加する (Story 1 Scenario 6 と同じ扱い)。
- URL を訂正しても、タイトルの再取得は行わない (タイトルは手で直す)。
- URL を訂正した結果、他の候補と同じ URL になる場合は確定できず、重複である旨を示す。
- 閉じている箱の見出しへ落とした場合、その箱の末尾に入る。
- 関連記事を持つ記事を削除した場合、関連記事も一緒に消える。削除前に件数を示して確認を取る。
- ページを再読み込みまたは離脱しようとした場合、候補が残っていればブラウザ標準の離脱確認を出す。登録成功による遷移では出さない。
- 登録中にログインの期限が切れた場合、登録は失敗として扱い、ログインし直す必要があることを示す。
- 記事 (関連記事を除く) は 100 件まで、関連記事は 1 記事あたり 20 件まで。上限に達したら追加の操作を受け付けず、上限であることを示す。
- 狭い画面では左右のカラムを縦に積み、同じ操作がすべて行える。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画面は管理者としてログインしている場合だけ使えなければならない (MUST)。ログインしていない場合は画面の存在を示さない。
- **FR-002**: 画面は 2 カラムで構成し、左に日付・URL 入力・未分類の箱・登録操作、右に固定 6 カテゴリの箱をこの順に縦に並べなければならない (MUST)。狭い画面では左を上、右を下に縦に積む。
- **FR-003**: 管理者は記事 URL を 1 件ずつ入力して未分類の箱の末尾に候補を追加できなければならない (MUST)。追加後、入力欄は空に戻る。
- **FR-004**: システムは追加された URL から記事タイトルを自動取得し、候補に設定しなければならない (MUST)。取得できない場合は候補をタイトル空で保持し、手入力が必要であることを示す。
- **FR-005**: タイトルの取得と翻訳 (specs/012 #105) が終わるまでは、候補を未分類に出さず、次の URL の実行を受け付けてはならない (MUST NOT)。処理中であることを表示する。カテゴリの推定は候補を出した後に行う (#110)。
- **FR-006**: システムは `http` / `https` 以外の URL と空入力を拒否し、理由をその場に表示しなければならない (MUST)。
- **FR-007**: システムは画面上のすべての候補 (関連記事を含む) と完全一致する URL の追加と訂正を拒否し、重複である旨を表示しなければならない (MUST)。
- **FR-008**: 候補はタイトル、URL のドメイン、サイトのアイコン、ホットの印 (付いている場合)、メニューを開く操作を表示しなければならない (MUST)。
- **FR-009**: カテゴリは固定の「セキュリティ、IT系、UI系、AI系、面白そうなツール・サービス、その他」とし、この順序で表示する (MUST)。管理者によるカテゴリの追加・変更・並び替えは行わない。
- **FR-010**: 各箱 (未分類と 6 カテゴリ) は見出しに名前と件数を常時表示しなければならない (MUST)。件数は関連記事を除く記事の数で、0 件でも表示する。
- **FR-011**: 各箱は見出しの操作で中身を畳み・開けなければならない (MUST)。畳んだ状態でもドロップ先として使える。
- **FR-012**: 管理者は記事 (関連記事を除く) を、任意の箱の任意の位置へドラッグ 1 回で移動できなければならない (MUST)。未分類からカテゴリ、カテゴリ間、カテゴリから未分類、箱の中での並び替えをすべて含む。
- **FR-013**: FR-012 の移動は、キーボードだけでも、タッチ操作でも行えなければならない (MUST)。
- **FR-014**: ドラッグ中は、動かしている候補と落ちる位置が分からなければならない (MUST)。
- **FR-015**: 候補のメニューは、編集、ホットの切り替え、関連記事にする / 外す、関連記事の上下移動 (関連記事のみ)、取得直後に戻す、削除を持たなければならない (MUST)。箱の移動はメニューに置かない。
- **FR-016**: 管理者は候補のタイトルと URL を訂正でき、確定前にやめた場合は訂正前の値が保たれなければならない (MUST)。URL を訂正しても候補は同じ 1 件として扱われ、箱と位置は保たれる。
- **FR-017**: 管理者は候補を 1 回の操作で取得直後の状態 (タイトル・URL) に戻せなければならない (MUST)。箱、位置、ホットの印、関連記事の関係は戻す対象に含めない。
- **FR-018**: ホットの印は記事 (関連記事を除く) にだけ付けられ、カテゴリとは独立していなければならない (MUST)。関連記事にした時点で印は外れる。
- **FR-019**: 「関連記事にする」は、同じ箱ですぐ上にある記事の関連記事の末尾に加えなければならない (MUST)。箱の先頭の記事、関連記事を持つ記事、上の記事の関連記事が 20 件に達している場合は選べない。関連記事は 1 段まで (関連記事の関連記事は作れない)。
- **FR-020**: 関連記事は親の記事と一緒に移動し、単独ではドラッグできてはならない (MUST NOT)。関連記事どうしの順序はメニューで変更できる。「外す」と親の直後に通常の記事として並ぶ。
- **FR-021**: 関連記事を持つ記事を削除するときは、関連記事も消えることを件数とともに示して確認を取らなければならない (MUST)。
- **FR-022**: Digest は全体で 1 つの日付を持ち、初期値は管理者の端末での当日とし、変更できなければならない (MUST)。
- **FR-023**: 管理者は候補一式を Digest 1 件分として登録でき、送信データは日付と、記事ごとにカテゴリ・ホットの印・タイトル・URL・関連記事 (タイトル・URL) を持つ配列で、カテゴリの固定順・箱内の順・関連記事の順を保たなければならない (MUST)。
- **FR-024**: システムは、カテゴリにある記事が 0 件、未分類の候補がある、タイトル空の候補がある、URL の追加の途中である、のいずれかのとき登録を拒否し、理由と該当する候補を示さなければならない (MUST)。
- **FR-025**: 登録に成功したとき、システムはトップ画面へ移らなければならない (MUST)。
- **FR-026**: 登録に失敗したとき、候補は失われてはならず (MUST NOT)、何を直せばよいかを短く示さなければならない (MUST)。サーバーの内部的なエラー文言はそのまま出さない。
- **FR-027**: 候補はページ滞在中のみ保持し、離脱・再読み込みで失われてよい。候補が残っている状態での離脱には確認を出さなければならない (MUST)。
- **FR-028**: 記事 (関連記事を除く) は 100 件、関連記事は 1 記事あたり 20 件を上限とし、上限に達したら追加・関連記事化を受け付けず、上限であることを示さなければならない (MUST)。
- **FR-029**: 外国語タイトルの言語判定・翻訳は本機能の範囲外とする。外国語タイトルは FR-016 の訂正で手動で書き換えられる。

### Key Entities

- **候補 (Candidate)**: Digest に入れる予定の記事 1 件。URL、タイトル、取得直後のタイトルと URL (戻す用)、タイトル取得状態 (取得済み / 失敗)、ホットの印、関連記事 (候補の並び、最大 20) を持つ。関連記事になった候補は自分の関連記事とホットの印を持たない。
- **箱 (Box)**: 候補を入れる場所。未分類 1 つと固定 6 カテゴリ。候補の並び順と開閉状態を持つ。候補はいずれか 1 つの箱に属するか、ある記事の関連記事である。
- **Digest (送信データ)**: 1 つの日付と、カテゴリの固定順 → 箱内の順に並べた記事の配列。1 回の登録で 1 件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 記事 10 件の Digest が、URL を貼り始めてから登録完了まで 5 分以内に終わる。
- **SC-002**: 記事 1 件の追加に必要な操作が「URL を貼る」「実行する」の 2 つに収まり、10 件連続で投入する間に入力欄以外を操作する必要がない。
- **SC-003**: 到達可能な一般的な記事ページの 90% 以上で、タイトルが自動取得される。
- **SC-004**: 候補 10 件の分類が、1 件あたりドラッグ 1 回で完了する。キーボードだけでも全件を分類できる。
- **SC-005**: トップ画面に表示された Digest のカテゴリ・順序・ホットの印・関連記事が、登録直前の配置と 100% 一致し、未分類の候補が混ざったまま登録されることが起こらない。
- **SC-006**: 不正な URL、重複 URL、登録条件未達、登録失敗のいずれでも、管理者は次に何をすべきかを画面上の表示だけで判断できる。

## Assumptions

- 利用者は管理者本人 1 名であり、同時に複数人が同じ Digest を編集することは想定しない。主な利用環境は PC で、狭い画面は崩れずに操作できれば足りる。
- 管理者の認証は specs/003 の仕組みをそのまま使う。
- タイトルの自動取得は、対象ページが公開されており認証なしで到達できることを前提とする。トップ画面の記事プレビューで使っているページ情報の取得の仕組みを、管理者向けに任意の URL で使えるようにして流用する。
- ホットの印の意味と表示は specs/004 に従う。
- 登録先は既存の Digest 登録 API で、同じ日付の Digest が複数あってもよい。1 つの Digest の中では URL が重複できない (関連記事を含む) ため、FR-007 で画面上でも防ぐ。
- 分類と並び替えはドラッグを主とする。キーボード・タッチでの同等操作は、ドラッグの仕組み自体が備えるもので満たし、別のメニュー操作は用意しない。
- 画面の見た目は Figma 基礎資料の原型 (node 6-65: URL Form / Draft item / Draft item menu / DragArea) を出発点とし、食い違う部分は `.agents/rules/frontend-ui-design.md` を優先する。メニューの「翻訳する」は範囲外のため出さない。
- 候補の一時保存 (下書き)、過去の Digest の閲覧・再編集、登録後に続けて次の Digest を作る流れは範囲外。
- 翻訳機能は後続の機能で追加する。FR-017 の「取得直後の状態」が翻訳前のタイトルの代わりになる。
