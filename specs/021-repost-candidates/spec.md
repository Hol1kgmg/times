# 再掲載の候補を探す軽量な検索 API (issue #176)

## 利用シナリオ

1. 管理者は登録・編集画面 (#171) で、タイトルか URL の一部から再掲載する記事を選ぶ。
2. 候補ごとに初掲載日と、子なら親の記事 (タイトル・URL) が分かり、どれを載せ直すか決められる。
3. 調査用の検索 (specs/020) と検証ページは今までどおり使える。

## 要件

- **FR-001**: 候補の検索は管理者専用にする。未ログインは 401。範囲は全期間。
- **FR-002**: 検索の条件は specs/020 と同じにする。タイトルと URL の部分一致で大文字小文字を区別せず、URL はパーセントエンコードした形とも照らす。語は 1〜100 文字で、空白だけは 400。
- **FR-003**: 候補は自分の記事のうち、隠しておらず、公開の Digest に 1 回以上載ったものだけにする (specs/018 FR-005)。
- **FR-004**: 候補ごとに ID・タイトル・URL・カテゴリ・初掲載日 (公開の掲載のうちいちばん古い日付) を返す。子なら親のタイトル・URL も返し、親を隠していれば親は返さない。
- **FR-005**: 再掲載の日付と HOT の履歴は返さない。調査用の検索の責務で、候補を選ぶのには要らないため。
- **FR-006**: 初掲載日の新しい順に、上限 50 件まで返す。
- **FR-007**: 選べない理由 (編集中の日付にすでに載っているなど) は返さない。画面で判定し、保存時に `repost-unavailable` で再検証する (specs/018)。

## 成功の基準

- **SC-001**: #171 の画面が、この検索だけで候補の一覧と選択を作れる。
- **SC-002**: 調査用の検索と検証ページの結果が変わらない。

## 対象外

検索モーダルと再掲載の行の UI (#171)、再掲載の保存と判定の変更、ページング。
