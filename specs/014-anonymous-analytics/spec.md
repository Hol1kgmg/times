# Feature Specification: 匿名 ID で記事別 UU・サイト UU・DAU・MAU を数える

**Feature Branch**: `014-anonymous-analytics`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: issue #119 (匿名ユーザー ID)、#120 (サイト全体の `page_view`)、#121 (記事別 UU・サイト UU・DAU・MAU の集計と検証) を 1 つにまとめる。同じブラウザを同じ匿名の読み手として数え、記事を押さずに見ただけの読み手も数え、GA4 の画面で記事ごとのクリック数と UU、サイト全体の UU・DAU・過去 30 日の MAU を確かめられるところまでにする。同意のバナーは出さず、トップの FAQ で計測していることと消し方を知らせる。技術スタックの説明は #122 で別に扱う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同じブラウザの読み手を 1 人として数える (Priority: P1)

読み手が同じブラウザで何度記事を押しても、集計先では同じ匿名の読み手として扱われる。別のブラウザや、サイトのデータを消した後は別の読み手になる。読み手の操作や記事の開き方は今と変わらない。

**Why this priority**: 今は記録ごとに読み手を区別する値を使い捨てにしているので、記事別 UU は記事のクリック数と同じ値になる。読み手を数えられなければ、ほかのどの指標も成り立たない。

**Independent Test**: 同じブラウザで 2 つの記事を押し、どちらの記録も同じ匿名 ID を持つことを確かめる。別のブラウザで押すと、別の匿名 ID になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 初めてサイトを開いたブラウザ, **When** 記事リンクを 2 回押す, **Then** 2 件の記録が届き、どちらも同じ匿名 ID を持つ
2. **Given** 記事を押したことのあるブラウザ, **When** ページを開き直して記事を押す, **Then** 前と同じ匿名 ID で届く
3. **Given** 別のブラウザ, **When** 記事を押す, **Then** 1 つ目のブラウザとは別の匿名 ID で届く
4. **Given** サイトのデータを消したブラウザ, **When** 記事を押す, **Then** 消す前とは別の匿名 ID で届く
5. **Given** 保存ができないブラウザ (保存を止めたプライベートモードなど), **When** 同じページで記事を 2 回押す, **Then** 2 件とも同じ匿名 ID で届く (ページを開き直すと変わってよい)
6. **Given** 既存の記事クリックの計測, **When** 本機能を入れた後に記事を押す, **Then** 記事の識別子・URL・Digest の日付、PC・モバイルの内訳、中クリック、プレビューで数えないこと、bot を除くことが今までどおり保たれる

---

### User Story 2 - 記事を押さずに見ただけの読み手も数える (Priority: P1)

読み手が公開画面を開くと、記事を押さなくても「このページが見られた」記録が 1 件届く。サイト内でほかの画面へ移ったときも、移った先の分が 1 件届く。記録は記事のクリックと同じ匿名 ID を持つ。

**Why this priority**: 記事を押した読み手しか数えられないと、サイト UU・DAU・MAU が出せない。

**Independent Test**: トップを開いて記録が 1 件届くことを確かめる。サイドバーからタイムラインへ移って、もう 1 件届くことを確かめる。どちらの記録も、同じブラウザの記事クリックと同じ匿名 ID であることを確かめる。

**Acceptance Scenarios**:

1. **Given** 公開画面, **When** 読み手がページを開く, **Then** 閲覧の記録が 1 件だけ届く
2. **Given** トップを開いている, **When** サイト内のリンクでほかの公開画面へ移る, **Then** 移った先の閲覧の記録が 1 件届く
3. **Given** 同じブラウザ, **When** ページを見て記事を押す, **Then** 閲覧の記録と記事のクリックの記録が同じ匿名 ID を持つ
4. **Given** 管理画面 (記事の登録・編集), **When** 開く・移る, **Then** 閲覧の記録は送られない
5. **Given** クエリ文字列の付いた URL, **When** ページを開く, **Then** 記録に載るページの場所にクエリ文字列が含まれない
6. **Given** 開発時の二重描画など、同じ表示で描画が繰り返される状況, **When** ページを開く, **Then** 閲覧の記録は 1 件だけ届く

---

### User Story 3 - 管理者が記事別 UU・サイト UU・DAU・MAU を確かめる (Priority: P1)

管理者が集計先 (GA4) の画面を開くと、記事ごとのクリック数と UU、サイト全体の UU、日ごとの UU、過去 30 日の UU を出せる。どの指標を、どの画面で、どの設定で出せばよいか、手順書を読めば分かる。手順書には、数字を読むときに気を付けることと、集計先で出せないときの代わりの方法も書いてある。

**Why this priority**: 記録が届いても、どう集計して読むかが決まっていなければ指標として使えない。

**Independent Test**: 手順書のとおりに、同じブラウザで複数回押す、別のブラウザで押す、ページを見るだけ、の 3 つを本番で試す。その後、集計先の画面で各指標が期待した値になることを確かめる。

**Acceptance Scenarios**:

1. **Given** ブラウザ A で記事 X を 2 回押し、ブラウザ B で記事 X を 1 回押した, **When** 管理者が手順書のとおりに記事ごとの集計を出す, **Then** 記事 X のクリック数は 3、UU は 2 になる
2. **Given** ブラウザ C ではページを見ただけで記事を押していない, **When** 管理者がサイト全体の UU を出す, **Then** A・B・C の 3 になる
3. **Given** 上の操作を同じ日に行った, **When** 管理者が日ごとの UU を出す, **Then** その日の値は 3 になる
4. **Given** 手順書, **When** 管理者が読む, **Then** 次のことが書いてある: 各指標の定義、集計先での出し方、「総ユーザー数」と「アクティブユーザー数」の違い、集計先の標準の月間指標は 28 日で 30 日の値は期間を指定して出すこと、タイムゾーンと日付の境目、データを残す期間、bot を除いていること、届かない記録があること、匿名 ID はブラウザ単位で実人数ではないこと、記事別 UU を足してもサイト UU にならないこと
5. **Given** 実測で集計先の値が期待と合わなかった, **When** 管理者が手順書を読む, **Then** 代わりの方法 (集計先の生データの書き出し、サイト側での保存と集計) とその条件が書いてある

---

### User Story 4 - 読み手が計測されていることと消し方を知る (Priority: P2)

読み手がトップの「よくある質問」を開くと、「何か記録してる？」という質問がある。答えには、閲覧数とクリック数を数えていること、そのために端末に匿名の ID を保存していること、その ID の消し方が話し言葉で書いてある。

**Why this priority**: 集計先の利用規約で、使っていることを知らせる必要がある。端末に ID を長く残すので、読み手が気付けて消せるようにする。ただし計測そのものの動きには関わらない。

**Independent Test**: トップの FAQ を開き、「何か記録してる？」の答えに 3 つのこと (何を数えるか、何を保存するか、どう消すか) が書いてあることを確かめる。

**Acceptance Scenarios**:

1. **Given** トップ, **When** 読み手が FAQ の「何か記録してる？」を開く, **Then** 集計先の名前、閲覧数とクリック数を数えていること、端末に匿名 ID を保存していること、サイトのデータを消すと ID が消えることが書いてある
2. **Given** FAQ, **When** 読み手が質問の一覧を見る, **Then** 計測の質問は技術スタックの説明とは別に、見出しで計測の話と分かる

---

### Edge Cases

- 保存ができないブラウザ: ページの中では同じ匿名 ID を使い回し、ページを開き直すと別の ID になってよい。記事の開き方や画面の表示は妨げない。
- 保存された値が壊れている、または形式が合わない: 新しい匿名 ID を作って保存し直す。
- 受付に、形式の合わない匿名 ID や大きすぎる本文が届いた: 集計先に送らない。
- 受付に、知らない種類の記録が届いた: 集計先に送らない。
- 記録の送信が失敗した: 読み手には示さず、再送しない (specs/013 と同じ)。
- bot (User-Agent で bot と分かるもの): 閲覧・クリックとも集計先に送らない。
- 管理者がログインしたまま公開画面を見た・押した: 読み手と同じく数える (specs/013 と同じ)。
- 同じブラウザで別のタブを同時に開いた: 同じ匿名 ID を使う。
- 画面を開いたまま日付をまたいだ: 記録が届いた時点の日付で数える。
- 同じページの中での再描画、同じ URL への移動: 閲覧の記録を増やさない。
- Digest の日付ページ (通知のリンク先) を開いた: そのページでは数えず、すぐ移るトップで 1 件として数える。日付ページは meta refresh でトップへ移るだけなので、両方で数えると 1 回の訪問が 2 件になる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ブラウザごとに匿名 ID を 1 つ作って端末に保存し、閲覧・記事のクリックの記録にその ID を付けなければならない (MUST)。ID は読み手が消すまで使い続け、期限は設けない。
- **FR-002**: 匿名 ID は無作為に作り、読み手の属性・ログインの有無・端末の情報から導いてはならない (MUST NOT)。
- **FR-003**: 端末に保存できないときは、ページの中だけで使い回す匿名 ID に切り替え、記録の送信を続けなければならない (MUST)。保存できないことで記事の開き方や画面の表示を妨げてはならない (MUST NOT)。
- **FR-004**: 保存された値が匿名 ID の形式に合わないときは、新しい ID を作って保存し直さなければならない (MUST)。
- **FR-005**: 受付は匿名 ID の形式と長さを検証し、合わない記録と大きすぎる本文を集計先に送ってはならない (MUST NOT)。
- **FR-006**: 受付は記録の種類 (閲覧・記事のクリック) ごとに形を検証し、知らない種類や形の合わない記録を集計先に送ってはならない (MUST NOT)。
- **FR-007**: システムは、公開画面を開いたときに閲覧の記録を 1 件、サイト内でほかの公開画面へ移ったときに移った先の分を 1 件送らなければならない (MUST)。同じ表示の再描画や同じ URL への移動で件数を増やしてはならない (MUST NOT)。
- **FR-008**: 管理画面 (記事の登録・編集とその一覧) では、閲覧の記録を送ってはならない (MUST NOT)。
- **FR-009**: 閲覧の記録に載せるページの場所からは、クエリ文字列とフラグメントを除かなければならない (MUST)。ページのタイトル以外の、画面に出ている内容や個人を特定しうる情報を載せてはならない (MUST NOT)。
- **FR-010**: 閲覧の記録と記事のクリックの記録は、同じブラウザでは同じ匿名 ID を持たなければならない (MUST)。
- **FR-011**: specs/013 の記事のクリックの決まり (FR-001〜FR-010、FR-012) は保たなければならない (MUST)。specs/013 FR-011 (読み手を識別しない、値を記録ごとに使い捨てる) は本仕様の FR-001 で置き換える。セッションの情報を載せないことは保つ。
- **FR-012**: 同意のバナーは出さない。トップの FAQ に「何か記録してる？」を 1 問足し、集計先の名前、閲覧数とクリック数を数えていること、端末に匿名 ID を保存していること、サイトのデータを消すと ID が消えることを話し言葉で書かなければならない (MUST)。
- **FR-013**: 手順書を残さなければならない (MUST)。管理者がそれを読めば、集計先の画面で次を出せる: 記事ごとのクリック数と UU、サイト UU、日ごとの UU (DAU)、過去 30 日の UU (MAU)。手順書には User Story 3 の受け入れシナリオ 4・5 に挙げたことを書く。
- **FR-014**: 本番の集計先で、同じブラウザでの複数回のクリック、別のブラウザ、ページを見ただけ、の 3 つを試す手順を残し、試した結果 (期待と合ったか、合わなかった点) を手順書に記録しなければならない (MUST)。

### Key Entities

- **匿名 ID**: ブラウザ 1 つを表す、無作為に作った識別子。端末に保存し、読み手が消すまで使う。実人数ではなくブラウザ単位の推定に使う。
- **閲覧**: 公開画面が 1 回表示されたことの記録。匿名 ID、ページの場所 (クエリなし)、ページのタイトルを持つ。
- **記事のクリック**: specs/013 の記録に匿名 ID を足したもの。記事の識別子、記事の URL、Digest の日付、匿名 ID を持つ。
- **指標**: 記事クリック数 (記事のクリックの件数)、記事別 UU (期間内にその記事を押した匿名 ID の数)、サイト UU (期間内に閲覧の記録を持つ匿名 ID の数)、DAU (日ごとのサイト UU)、MAU (過去 30 日のサイト UU。暦の月ではない)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同じブラウザから送られた閲覧と記事のクリックの記録は、サイトのデータを消すまで 100% が同じ匿名 ID を持つ。
- **SC-002**: User Story 3 の実測 (ブラウザ A で 2 回、ブラウザ B で 1 回押し、ブラウザ C は見るだけ) で、記事のクリック数 3、記事別 UU 2、サイト UU 3、その日の DAU 3 が集計先の画面で確かめられる。合わなければ、合わなかった理由と代わりの方法が手順書に記録されている。
- **SC-003**: 管理画面を開いたり移ったりしても、集計先に届く閲覧の記録は 0 件である。
- **SC-004**: 集計先に届く閲覧の記録のうち、ページの場所にクエリ文字列を含むものは 0 件である。
- **SC-005**: 公開画面を 1 回開くと、閲覧の記録がちょうど 1 件届く。
- **SC-006**: 端末に保存できないブラウザでも、記事が開くことと画面の表示に失敗が 0 件である。
- **SC-007**: 読み手はトップの FAQ から、何を数えていて何を保存しているか、どう消すかを 1 問で知ることができる。
- **SC-008**: specs/013 の成功基準 (SC-001〜SC-006) を本機能の後も満たす。

## Assumptions

- 集計先は specs/013 と同じ GA4 で、ブラウザ → サイトの受付 → GA4 の経路も同じにする。閲覧の記録は GA4 の標準の閲覧イベント (`page_view`) として送り、`page_location` と `page_title` を載せる。
- 匿名 ID は GA4 の `client_id` として使う。GA4 でサイト UU や記事別 UU を出すには、匿名 ID を毎回同じにするだけで足りる見込みである。ただし Measurement Protocol だけで送ったときに「総ユーザー数」「アクティブユーザー数」が期待どおりになるかは公式に明記されていないので、User Story 3 の実測で確かめる。
- 保存先は端末のブラウザのストレージ (localStorage) で、Cookie は使わない。サーバーに毎回送られる値を増やさないため。
- 同意のバナーは出さない。利益を目的としない個人サイトで、ブラウザから第三者に直接送らせず、匿名 ID はほかの個人情報と結び付かない。EU 向けのサイトではない (会話での判断。法律家の確認ではない)。
- 「公開画面」はトップ・タイムラインの 2 つを指す。Digest の日付ページはトップへ移るだけなので含めない。管理画面 (`/admin/*`)、ログイン画面、ログインのコールバック、ヘルスチェックは含めない。ログイン画面のパスは秘密なので、集計先に載せない。
- 管理者自身の閲覧・クリックは除かない (specs/013 と同じ)。
- GA4 のプロパティのタイムゾーンとデータ保持期間は、今の設定を手順書に書き写す。変える必要があるかは実測の後で決める。
- 集計結果をサイトの管理画面に出すこと、BigQuery Export やサイト側での保存の実装、技術スタックの説明 (#122) は本仕様に含めない。代わりの方法は手順書に条件を記録するだけにする。
