# Feature Specification: Digest のタイムライン

**Feature Branch**: `008-digest-timeline`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: 新しいページで、公開の Digest を記事ごと一覧で frontend へ渡し、トップの投稿ブロック (記事カード) と同じ UI で、日付順に並んだチャットログのように Digest を連ねて見せるための API。ログインしているユーザーだけが使える。並びは日付の新しい順 (同じ日付なら後に登録したものが先) で、件数は Digest の件数 (日数) で数える。続きは「この日付より前」を指定して読み足す (指定した日付は含まない)。Digest のない日は詰める。1 日分の中の記事の並びは登録時の順を保つ。古いものを上に並べるチャットログの順への並べ替えと、画面そのものは範囲外。

**追加 (2026-11-03)**: 返すのは管理者アカウントのユーザーが作成した Digest だけに絞る。同じ作成者の Digest は日付が重複しない仕様で、管理者は 1 アカウントしか作れない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直近の Digest を記事ごとまとめて受け取る (Priority: P1)

ログインしているユーザーがタイムラインを開くと、公開の Digest が日付の新しい順に、1 日分ずつ記事を含んだ形で決まった件数まで返る。画面はこれを使い、トップの投稿ブロックと同じ見た目で日付ごとの投稿を連ねる。

**Why this priority**: タイムラインの最初の表示に要る。これがないと画面を作れない。

**Independent Test**: 公開の Digest を 10/20・10/22・10/25 に登録した状態で件数 2 を指定して求め、10/25 → 10/22 の 2 件が記事つきで返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 公開の Digest が複数ある, **When** 指定なしで求める, **Then** 日付の新しい順に、既定の件数 (7 件) まで返る
2. **Given** 公開の Digest が 3 件ある, **When** 件数 2 を指定して求める, **Then** 新しい 2 件だけが返る
3. **Given** 10/20・10/22・10/25 に Digest がある (間の日はない), **When** 件数 3 で求める, **Then** 3 件とも返る (件数は日数ではなく Digest の件数で数える)
4. **Given** 返った Digest, **When** 中身を見る, **Then** 各 Digest はトップの最新の Digest と同じ形 (カテゴリ・ホットトピックの印・関連記事を含む記事の並び) を持ち、記事は登録時の順で並ぶ
5. **Given** 1 日分の記事が件数の上限より多い, **When** 求める, **Then** その日の記事は途中で切られず、すべて含まれる
6. **Given** 下書き・非公開の Digest がある, **When** 求める, **Then** それらは含まれず、件数にも数えない
7. **Given** 公開の Digest が 1 件もない, **When** 求める, **Then** 空の一覧が返る (エラーにしない)

---

### User Story 2 - さかのぼって古い Digest を読み足す (Priority: P1)

ユーザーがタイムラインを上へさかのぼると、いま表示しているいちばん古い日付より前の Digest が、同じ並びと件数の規則で返る。これを繰り返して、最初の Digest までたどれる。

**Why this priority**: チャットログとして過去をたどれることがこの画面の目的。最新の数件だけなら、トップで足りる。

**Independent Test**: 公開の Digest を 10/20・10/22・10/25 に登録した状態で、件数 2 で求めて 10/25・10/22 を得たあと、「10/22 より前」を指定して求め、10/20 だけが返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 10/20・10/22・10/25 に公開の Digest がある, **When** 「10/22 より前」を指定して求める, **Then** 10/20 だけが返る (指定した日付そのものは含まない)
2. **Given** 前回の結果のいちばん古い日付を指定して読み足す, **When** 最後まで繰り返す, **Then** 公開の Digest がすべて 1 回ずつ現れ、重複も抜けもない
3. **Given** 返った件数が指定した件数より少ない, **When** それを見る, **Then** それより古い公開の Digest はない
4. **Given** 指定した日付より前に公開の Digest がない, **When** 求める, **Then** 空の一覧が返る
5. **Given** 読み足す間に新しい Digest が登録された, **When** 続きを求める, **Then** 続きの結果はずれない (既に返した Digest が再び現れない)

---

### User Story 3 - ログインしていない人には返さない (Priority: P1)

タイムラインはログインしているユーザーのための画面で、ログインしていない人には返さない。ログインしていない人が見られるのは、これまでどおりトップの最新 1 日分だけ。

**Why this priority**: 過去の Digest をまとめて見せる範囲を、ログインユーザーに限るため。

**Independent Test**: ログインせずに求め、拒否されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログインしていない, **When** 求める, **Then** 認証が必要として拒否される
2. **Given** ログインしている, **When** 求める, **Then** 一覧が返る

---

### User Story 4 - 管理者が作った Digest だけを返す (Priority: P1)

タイムラインに並ぶのは、サイトの管理者が作った Digest だけ。誰がログインして求めても、返るのは同じ管理者の Digest で、ログインしている本人の Digest ではない。

**Why this priority**: タイムラインはサイトとして公開する Digest の並び。管理者以外の作成者のデータが混ざると、同じ日付の Digest が 2 件並び、続きの起点も一意に決まらない。

**Independent Test**: 管理者の公開の Digest (10/20) と、管理者ではない作成者の公開の Digest (10/21) がある状態で求め、10/20 だけが返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 管理者と管理者ではない作成者の公開の Digest がある, **When** 求める, **Then** 管理者の Digest だけが返る
2. **Given** 管理者のアカウントが設定されていない, **When** 求める, **Then** 空の一覧が返る (他の作成者の Digest を代わりに返さない)
3. **Given** 管理者の GitHub ユーザー名の大文字小文字が設定と違う, **When** 求める, **Then** ログインの判定と同じく同じ管理者として扱う
4. **Given** 管理者を別のアカウントに変え、前の管理者の公開の Digest が残っている, **When** 求める, **Then** 今の管理者の Digest だけが返る

### Edge Cases

- 件数の指定が 1 未満・31 超・数値でない: 不正な入力として拒否する
- 日付の指定が日付の形でない: 不正な入力として拒否する
- 未来の日付を指定: 拒否せず、その日付より前の Digest を返す
- 同じ日付の公開の Digest: 管理者に絞るので起きない (同じ作成者の Digest は日付が重複しない)
- 公開の Digest を非公開にした: 次に求めたときから含まれない
- 記事が 0 件の公開の Digest: 記事の空の Digest として返す (日付は返す)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、公開の Digest を、それぞれの記事と関連記事を含めて複数件まとめて返さなければならない
- **FR-002**: 並びは日付の新しい順としなければならない。FR-010 で作成者を 1 人に絞るので、同じ日付の Digest は並ばない
- **FR-003**: 返す件数の上限は Digest の件数 (日数) で数え、1〜31 で指定でき、指定がなければ 7 件としなければならない。範囲外は不正な入力として拒否する
- **FR-004**: 1 件の Digest に含まれる記事は、件数の上限によって途中で切ってはならない
- **FR-005**: 日付を指定したら、その日付より前 (その日付を含まない) の Digest だけを返さなければならない。指定がなければ最新から返す
- **FR-006**: Digest のない日は詰めて返し、空の日を埋めてはならない
- **FR-007**: 各 Digest の形と、その中の記事の並び (登録時のカテゴリ順・カテゴリ内順) は、トップの最新の Digest と同じでなければならない
- **FR-008**: 下書き・非公開の Digest は含めてはならない
- **FR-009**: ログインしている場合にだけ返し、それ以外は認証が必要として拒否しなければならない。管理者に限らない (今ログインできるのは管理者だけ)
- **FR-010**: 返す Digest は、管理者アカウントのユーザーが作成したものだけに絞らなければならない。管理者の判定はログインの許可と同じ規則 (設定された GitHub ユーザー名と一致、大文字小文字は区別しない) とし、求めた本人が誰かでは絞らない。管理者が設定されていなければ空の一覧を返す

### Key Entities

- **Digest**: 1 日付分の記事のまとまり。日付・ステータス・記事の並びを持つ (既存)
- **タイムラインの 1 ページ**: 新しい順に並んだ公開の Digest の列。続きの起点は、そのページのいちばん古い Digest の日付

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログインユーザーは、1 回の要求で直近 7 日分 (7 件) の Digest を記事ごと受け取れる
- **SC-002**: 続きの指定を繰り返すと、公開の Digest をすべて、重複も抜けもなくたどれる
- **SC-003**: 現在のデータ量 (Digest 数十〜数百件、1 件あたり記事数十件) で、1 ページ分が体感で待たずに返る (1 秒未満)
- **SC-004**: ログインしていない状態で求めた場合、100% 拒否される
- **SC-005**: 返る Digest に、下書き・非公開のものと、管理者以外が作成したものが 1 件も含まれない

## Assumptions

- 管理者は 1 アカウントだけという決まりは、データベースの制約ではなく、設定した GitHub ユーザー名のアカウントにだけログインを許す運用で守っている。ユーザーの記録にロールはなく、件数やユーザー名の重複を制限する制約もない
- 絞り込みは、求めた時点で設定されている管理者のユーザー名で行う。管理者を別のアカウントに変えたら、前の管理者が作った Digest はタイムラインに出なくなる (今の管理者の Digest だけを並べる意図どおり)
- 管理者が GitHub のユーザー名を変えたあと一度もログインせず、空いた旧名を取った別人のユーザーの記録が残っていると、同じユーザー名の作成者が 2 人になり、両方の Digest が混ざる。ユーザー名は本人がログインするたびに最新になるので、この状況はまず起きないとして受け入れる。ユーザー名に重複を禁じる制約は、名前を引き継いだ人のログインを失敗させるので置かない
- 一般ユーザーのアカウントは後続の機能で作り、そのときもこの機能はログインの確認だけで使え、返るのは管理者の Digest のまま
- 同じ作成者の同じ日付の Digest は 1 件までという既存の制約がデータベースにあり、FR-010 で作成者を管理者 1 人に絞るので、日付を続きの起点にしても取りこぼしも重複も出ない (上のユーザー名の重複が起きた場合を除く)
- トップの最新の Digest は作成者で絞っていないが、今は管理者しか Digest を作れないので結果は一致する。一般ユーザーが Digest を作れるようにするときに、トップも揃える
- 古いものを上に並べるチャットログの順への並べ替え、上へのスクロールで読み足す振る舞い、画面そのもの (ルート・見た目) は後続の機能で作る。この機能はデータを返す部分と、それを frontend から呼ぶ入り口までを作る
- 記事の概要 (プレビューカード) は、トップと同じく表示側が記事に注目したときに取得する。この機能では返さない
- ログインしていない人に見せる範囲は、これまでどおりトップの最新 1 日分だけで変えない
