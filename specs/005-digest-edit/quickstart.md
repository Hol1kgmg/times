# Quickstart: 登録済みの Digest を編集する

## 前提

ローカルの DB・backend・frontend が起動し、管理者でログインできること (docs/admin-login.md)。Digest を 2 件以上登録しておく (`/admin/digests/new`)。

## 自動チェック

```sh
just be-gen                 # openapi.yaml と SQL を変えたので再生成。差分は同じコミットに含める
just lint && just test      # go test (router 3 行) と Vitest (fromDigest)
just fe-typecheck
just fe-test-e2e            # digest-edit.spec.ts と既存の digest-new.spec.ts
```

## 手動確認

| # | 操作 | 期待 | 対応 |
|---|---|---|---|
| 1 | ログアウトして `/admin/digests` と `/admin/digests/<登録済みの日付>/edit` を開く | どちらも 404。サイドバーに「記事を編集」がない | FR-001, FR-002 |
| 2 | ログインしてサイドバーの「記事を編集」 | 日付が新しい順に並ぶ | FR-003 |
| 3 | 日付を選ぶ | 保存済みの配置 (カテゴリ・順序・ホット・関連記事) で並び、タイトルの取得中表示が出ない | FR-006 |
| 4 | 何も変えずに保存 | 日付一覧へ戻る。5 分後のトップが保存前と同じ | SC-002 |
| 5 | タイトルを直す → 「変更を戻す」 | 保存済みのタイトルに戻る。ホットや位置は変わらない | FR-016, FR-017 |
| 6 | 別の日付の Digest にある URL を追加して保存 | 拒否され、その記事に印が付き、編集内容は残る | FR-008, FR-013 |
| 7 | この Digest の URL を残したまま保存 | 拒否されない | FR-008 |
| 8 | 日付を登録済みの別の日付に変えて保存 | 「その日の Digest は登録済みです」が出る | FR-009 |
| 9 | 8 の状態で、さらに別 Digest の URL も含めて保存 | 日付の衝突だけが出る | FR-010 |
| 10 | 日付を一度変えて元に戻して保存 | 拒否されない | US2-4 |
| 11 | 日付を未登録の日に変えて保存 | 一覧が新しい日付になり、古い日付は消える | FR-009 |
| 12 | 何か変えてからサイドバーで別の画面へ | 「保存してない変更があります」の確認が出る。変えずに移ると出ない | FR-014 |
| 13 | 別のタブでログアウトしてから保存 | ログインし直すよう出て、編集内容は残る | Edge Cases |
