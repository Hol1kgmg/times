# Feature Specification: 記事一覧 (Digest 閲覧) 画面

**Feature Branch**: `002-article-digest-view`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: 記事データを表示する機能仕様を用意したい

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 最新の Digest を読む (Priority: P1)

読者はサイトを開くと、最新の Digest が「日付 → カテゴリ → 記事タイトル」の順で並んだ一覧を見る。カテゴリは固定の順序で並び、記事が 1 件もないカテゴリは表示されない。読者は気になった記事のタイトルを選ぶと、元の記事が別のタブで開く。タイトル以外の余計な情報がなく、その日に何が集まったかを一目で把握できる。

**Why this priority**: サイトの主目的は「集めた記事を読む」ことであり、最新 1 件分の Digest を読めるだけで価値がある。Story 2 はこの一覧がなければ成立しない。

**Independent Test**: 記事が複数カテゴリにわたる Digest が 1 件ある状態でサイトを開き、日付・カテゴリ・タイトルが固定順で並び、タイトルから元記事へ移動できることを確認できる。

**Acceptance Scenarios**:

1. **Given** Digest が 1 件以上ある状態, **When** サイトのトップを開く, **Then** 最も新しい日付の Digest が、その日付を見出しにして表示される
2. **Given** 最新の Digest が表示されている, **When** 一覧を見る, **Then** 記事はカテゴリごとにまとまり、カテゴリは固定の順序 (Digest 作成時と同じ順序) で並ぶ
3. **Given** あるカテゴリに記事が 1 件もない Digest, **When** 一覧を見る, **Then** そのカテゴリの見出しは表示されない
4. **Given** 同じカテゴリに複数の記事がある, **When** 一覧を見る, **Then** 記事は Digest 作成時に決めた順序で並ぶ
5. **Given** 一覧に記事がある, **When** 記事タイトルを選ぶ, **Then** 元の記事が別のタブで開き、一覧の画面はそのまま残る
6. **Given** Digest が 1 件もない状態, **When** サイトのトップを開く, **Then** エラーではなく「まだ記事がない」ことが分かる表示になる

---

### User Story 2 - 記事の概要を確認する (Priority: P2)

読者はタイトルだけで読むか決めかねる記事について、元の記事を開かずに概要 (ページの説明文) と掲載元 (ドメイン) を確認する。概要が取得されていない記事は、タイトルと掲載元だけが表示される。

**Why this priority**: タイトルだけでは判断できない記事を開く手間を減らす。一覧が読めるだけでも価値はあるので P1 の後に置く。

**Independent Test**: 概要ありの記事と概要なしの記事が混在する Digest を表示し、前者は概要と掲載元が、後者は掲載元だけが確認できることを確認できる。

**Acceptance Scenarios**:

1. **Given** 概要が登録されている記事, **When** その記事に注目する, **Then** 元の記事を開かずに概要と掲載元が確認できる
2. **Given** 概要が登録されていない記事, **When** その記事に注目する, **Then** 掲載元は表示され、概要の欄は空欄ではなく存在しない
3. **Given** 概要が長い記事, **When** 一覧を見る, **Then** 概要は一定の長さで打ち切られ、一覧の並びを崩さない
4. **Given** モバイル幅の画面, **When** 一覧を見る, **Then** タイトルと掲載元が優先して表示され、概要は表示されないか折りたたまれる

---

### Edge Cases

- Digest が複数ある場合も、表示するのは最も新しい日付の 1 件だけ。同じ日付の Digest が複数回登録された場合は最後に登録されたものを表示し、統合はしない。
- タイトルが空の記事は Digest 作成時に登録できないため、一覧では扱わない。万一空であれば URL をタイトルの代わりに表示する。
- 記事の URL がリンクとして開けない形式 (作成時の検証をすり抜けた場合) でも、一覧の表示は崩れず、その記事だけリンクにならない。
- 掲載元 (ドメイン) は URL から機械的に導く。`www.` などの接頭辞の除去は行わない。
- 1 件の Digest に 100 件の記事があっても、一覧は 1 画面 (縦スクロール) で読める。ページ分割はしない。
- 記事データの取得に失敗した場合、空の一覧ではなく「読み込めなかった」ことを表示し、再読み込みで回復できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはサイトのトップで、最も新しい日付の Digest を表示しなければならない (MUST)。
- **FR-002**: システムは 1 件の Digest を「日付見出し → カテゴリ見出し → 記事タイトルの並び」の階層で表示しなければならない (MUST)。
- **FR-003**: カテゴリの表示順は Digest 作成機能 (001) で定めた固定順「セキュリティ、ホットトピック、IT系、UI系、AI系、面白そうなツール・サービス、その他」に従わなければならない (MUST)。記事のないカテゴリは表示しない (MUST NOT)。
- **FR-004**: カテゴリ内の記事の並びは、Digest 作成時に決めた順序を保たなければならない (MUST)。
- **FR-005**: 各記事タイトルは元の記事へのリンクとし、選ぶと別のタブで開かなければならない (MUST)。
- **FR-006**: 各記事は、タイトル・元記事の URL・掲載元 (URL から導いたドメイン)・概要 (登録されている場合のみ) を表示に使う (MUST)。概要がない記事に概要の領域を設けてはならない (MUST NOT)。
- **FR-007**: 概要は表示上一定の長さで打ち切られなければならない (MUST)。全文の表示は求めない。
- **FR-008**: Digest が 1 件もないとき、システムは記事がない旨を表示しなければならない (MUST)。
- **FR-009**: 過去の日付の Digest への移動・日付指定の URL は本機能の範囲外とする。表示は常に最新 1 件のみ (MUST)。
- **FR-010**: 記事データの読み込みに失敗したとき、システムは失敗を表示し、読者が再読み込みで回復できなければならない (MUST)。
- **FR-011**: 一覧は既存の UI デザインルール (白背景・境界線・固定トークン・タイポグラフィ階層) に従い、モバイル幅ではタイトルと掲載元を優先して表示しなければならない (MUST)。
- **FR-012**: 閲覧は認証なしで誰でもできる (MUST)。既読管理・お気に入り・検索・フィルタは本機能の範囲外とする。
- **FR-013**: 表示する記事データは Digest 作成機能 (001) の送信データと同じ形とし、本機能では手書きの固定データを読む (MUST)。登録内容の永続化と、永続化されたデータへの切り替えは後続の機能で行う。

### Key Entities

- **Digest**: ある日付 1 つ分の記事のまとまり。日付と、カテゴリ順・カテゴリ内順に並んだ記事の列を持つ。001 で登録される送信データと同じ内容。
- **記事 (Article)**: Digest に含まれる 1 件。タイトル、元記事の URL、カテゴリ、カテゴリ内の並び順、概要 (任意) を持つ。掲載元 (ドメイン) は URL から導く派生値で、保存しない。
- **カテゴリ (Category)**: 001 と同じ固定の 7 つ。順序も固定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 読者はトップを開いてから 3 秒以内に最新の Digest の記事タイトルを読み始められる。
- **SC-002**: 記事 1 件を開くのに必要な操作は「タイトルを選ぶ」の 1 回で、一覧の画面は失われない。
- **SC-003**: 表示された記事の並び (カテゴリ順・カテゴリ内順) と件数が、登録された Digest の内容と 100% 一致する。
- **SC-004**: 概要が登録された記事は、元の記事を開かずに 100% 概要を確認できる。
- **SC-005**: Digest がない・読み込めない、のいずれの場合も、読者は次に何をすべきかを画面上の表示だけで判断できる。

## Assumptions

- 表示する Digest の形は 001 の送信データ (日付 + カテゴリ / タイトル / URL / 概要 の配列) と同じで、本機能はその形を前提に読むだけで変更しない。
- 001 の登録先はスタブで永続化されないため、当面は手書きの固定データ (複数日付を含んでよい) から最新 1 件を選んで表示する。永続化が入った時点でデータの読み元だけを差し替え、表示の仕様は変えない。
- 過去の Digest の閲覧は「まずは最新だけ」の方針により範囲外とし、必要になったら別機能として仕様を追加する。
- 概要は 001 で取得した「ページの説明文」であり、本機能で新たに取得や要約はしない。
- 読者は不特定多数を想定し、閲覧に認証は要らない。編集や削除は本機能に含めない。
- 記事の日時 (何時に登録したか) は表示しない。日付見出しのみで十分とする。
- カテゴリの固定一覧と順序は 001 のものを共有する。変更が必要になったら 001 と本仕様を同時に改訂する。
- 既存のサンプル画面 (Items 一覧・詳細) は本機能で置き換える対象であり、トップは本機能の一覧になる。置き換えの詳細は計画段階で決める。
- 記事カード (影付き・角丸) と一覧の見た目はデザイン基礎資料 (Figma) の「記事一覧」「記事カード」に従う。
- UI は既存のデザインルール (`.agents/rules/frontend-ui-design.md`) に従う。
