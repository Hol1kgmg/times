# Feature Specification: 記事タイトルを固有名称を残して日本語に翻訳する

**Feature Branch**: `012-title-translation`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: issue #99「記事タイトルの翻訳 (固有名称の保護と編集画面からの手動実行)」。固有名称の抽出は Workers AI の clef を使う。編集画面から記事ごとに手動で翻訳を実行でき、手動実行では翻訳が必要かの判定 (#105) を通さない。翻訳は抽出と翻訳の関数として作り、判定は呼び出し側 (#105) で挟む。元に戻すボタンは既存の revert で、翻訳後のタイトルの持ち方 (title を上書きするか別の項目に持つか) と保存後に原文へ戻せるかを仕様で決める。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 英語のタイトルを編集画面から日本語にする (Priority: P1)

管理者が登録・編集画面で候補の「記事を編集」のモーダルを開き、タイトル欄の右端の「翻訳」を押すと、システムがタイトルの固有名称 (React、TypeScript、TanStack Start など) を英語のまま残して日本語に翻訳し、タイトル欄を翻訳結果に置き換える。管理者はそのまま確定するか、欄で手で直してから確定し、登録する。公開画面には登録した日本語のタイトルが出る。

**Why this priority**: 英語のタイトルを日本語で読めるようにすることが、この機能の目的そのもの。

**Independent Test**: `Building Apps with React and TypeScript` の候補の編集モーダルで翻訳を押して確定し、タイトルが `React` と `TypeScript` を英語のまま含む日本語になり、登録後に公開画面で同じタイトルが出ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 英語のタイトルの候補の編集モーダル, **When** 翻訳を押す, **Then** タイトル欄が日本語の翻訳結果に置き換わり、固有名称は原文と同じ表記 (大文字・小文字・記号を含む) で残る
2. **Given** 翻訳したタイトルを確定した候補, **When** 登録する, **Then** 公開画面に翻訳したタイトルが出る
3. **Given** 翻訳したタイトル欄, **When** 管理者が欄を手で直して確定し、登録する, **Then** 直したタイトルで保存される
4. **Given** 翻訳中の編集モーダル, **When** 結果を待つ, **Then** 翻訳中であることがモーダルに出て、翻訳は重ねて実行できない
5. **Given** 日本語のタイトルや固有名称だけのタイトル欄, **When** 翻訳を押す, **Then** 判定をせずに翻訳を実行する (翻訳が必要かの判定は #105 の自動実行でだけ行う)

---

### User Story 2 - 翻訳の失敗を公開しない (Priority: P1)

翻訳が失敗したとき、または翻訳結果から固有名称が欠けたり表記が変わったりしたとき、システムはタイトル欄を変えず、翻訳できなかったことを編集モーダルに示す。管理者は翻訳をやり直すか、手でタイトルを直す。

**Why this priority**: 固有名称が崩れたタイトルや失敗した結果がそのまま公開されると、記事が何の話か分からなくなる。

**Independent Test**: 翻訳結果から固有名称が欠けるように外部の翻訳を差し替え、タイトル欄が原文のまま残り、翻訳できなかった旨が出ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 翻訳結果の固有名称の表記が原文と違う, **When** 翻訳が終わる, **Then** タイトル欄は変わらず、翻訳できなかったことがモーダルに出る
2. **Given** 一時的な通信の失敗, **When** 翻訳を押す, **Then** 回数を限って自動で再試行し、それでも失敗すればタイトル欄は変わらない
3. **Given** 翻訳に失敗した編集モーダル, **When** もう一度翻訳を押す, **Then** 翻訳をやり直せる
4. **Given** 翻訳に失敗した編集モーダル, **When** そのまま確定して登録する, **Then** 原文のタイトルで保存される

---

### User Story 3 - 翻訳を取り消して原文に戻す (Priority: P2)

翻訳結果が気に入らないとき、管理者は元に戻すボタンで候補のタイトルを原文に戻す。

**Why this priority**: 誤って翻訳を押しても戻せれば、手動実行に確認の手順を挟まずに済む。

**Independent Test**: 翻訳を確定した候補で、行のメニューの「変更を戻す」を押し、タイトルが原文に戻ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 翻訳を確定して、まだ登録していない候補, **When** 元に戻すを押す, **Then** タイトルが翻訳前の原文に戻る
2. **Given** 翻訳して登録した記事, **When** 編集画面で開き直して元に戻すを押す, **Then** 保存した日本語のタイトルに戻る (原文は保存しないので、保存後は原文に戻せない)

---

### Edge Cases

- 翻訳を待つ間に編集モーダルを閉じた: 翻訳の結果は捨てる。
- 翻訳を待つ間に管理者がタイトル欄を手で直した: 手で直したタイトルを優先し、翻訳の結果で上書きしない。
- 固有名称が 1 つも見つからないタイトル: 守る語なしでそのまま翻訳する。
- 固有名称の抽出が失敗した: 守る語が分からないまま翻訳すると固有名称が崩れるおそれがあるので、翻訳しない。翻訳できなかったことを示す。
- 抽出された語が原文にない、または他の語の一部と重なる (TanStack / TanStack Start): 原文にない語は捨て、重なる語は長いほうを守る。
- タイトル欄が空: 翻訳を押せない。
- 子記事の候補: 親の候補と同じく編集モーダルから翻訳できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理者は、登録・編集画面の候補の編集モーダルで、タイトル欄の翻訳を実行できなければならない (MUST)。
- **FR-002**: システムは、翻訳の前にタイトルから固有名称を抽出し、原文に含まれない語を捨て、重なる語は長いほうを残さなければならない (MUST)。
- **FR-003**: システムは、抽出した固有名称を原文の表記のまま残して、タイトルを英語から日本語に翻訳しなければならない (MUST)。
- **FR-004**: システムは、翻訳結果に固有名称がすべて原文と同じ表記で含まれるかを確かめ、満たさない結果をタイトル欄に適用してはならない (MUST NOT)。原文より多く出てくる英単語がある結果 (固有名称の一部が span の外に書き足されたもの) も適用してはならない (MUST NOT)。
- **FR-005**: 抽出・翻訳・確認のいずれかが失敗したら、タイトル欄を変えず、翻訳できなかったことを編集モーダルに示さなければならない (MUST)。一時的な通信の失敗は、回数を限って再試行しなければならない (MUST)。
- **FR-006**: 翻訳結果はタイトル欄を置き換え、確定で候補のタイトルになる。手で入力したタイトルと同じく管理者が直せなければならない (MUST)。
- **FR-007**: 元に戻すボタンで、翻訳した候補のタイトルを翻訳前の原文に戻せなければならない (MUST)。
- **FR-008**: 公開画面は保存済みのタイトルを出し、閲覧のたびに翻訳を実行してはならない (MUST NOT)。
- **FR-009**: 翻訳が進んでいる間は、同じ編集モーダルで翻訳を重ねて実行させてはならない (MUST NOT)。
- **FR-010**: 翻訳は管理者だけが使えなければならない (MUST)。翻訳の外部サービスの認証情報はブラウザに渡してはならない (MUST NOT)。
- **FR-011**: 抽出と翻訳は、翻訳が必要かの判定を含まない単位として呼べなければならない (MUST)。判定は自動実行 (#105) の呼び出し側で挟む。
- **FR-012**: 固有名称の抽出の手段がない環境 (ローカル開発) では、翻訳を押せなくしなければならない (MUST)。固有名称を守らずに翻訳してはならない (MUST NOT)。

### Key Entities

- **固有名称**: タイトルから抽出した、翻訳しない語。原文の表記 (大文字・小文字・記号) のまま翻訳結果に残る。
- **翻訳の結果**: 原文のタイトル、日本語のタイトル、守った固有名称、成否。成功したものだけがタイトル欄に適用される。
- **記事のタイトル**: 公開画面に出るタイトル。翻訳した記事では日本語のタイトル。原文のタイトルは保存しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 翻訳が成功したタイトルのうち、固有名称の表記が原文と異なるものの割合が 0% である。
- **SC-002**: 翻訳に失敗した候補で、タイトルが原文から変わったものの件数が 0 件である。
- **SC-003**: 1 日約 10 件の英語のタイトルを、1 件あたり数秒以内に翻訳できる。
- **SC-004**: 公開画面の表示で、翻訳の外部サービスを呼ぶ回数が 0 回である。
- **SC-005**: 翻訳した候補は、登録前であれば 100% 元に戻すボタンで原文に戻せる。

## Assumptions

- 固有名称の抽出には、011 で導入済みの Workers AI の clef を使う。jev は使わない。011 で使った `choice` 型の質問のほかに、タイトルから語を抜き出す使い方ができるかは plan で確かめる。
- 翻訳には Google Cloud Translation を使い、固有名称は HTML 入力の `translate="no"` で守る方式を第一候補にする。期待どおりに守れなければ、plan でプレースホルダー方式や Glossary 方式に切り替える。
- 翻訳は編集モーダルの上で行い、結果は確定するまでモーダルの欄に、登録するまで画面の上だけにある (011 の推定と同じ)。翻訳の処理状態 (`needs_review` など) は保存しない。失敗した結果はタイトルに適用しないので、そのまま公開されることはない。
- 翻訳結果は記事のタイトルを置き換えるだけにし、原文は保存しない。保存の形・DB・API は変えない。保存後に原文が欲しくなったら、URL を追加し直してタイトルを取り直す。
- ローカル開発 (`just fe-dev`) には固有名称の抽出の手段がないので、翻訳ボタンを押せなくする (011 の推定と同じ扱い)。翻訳はデプロイ先でだけ試せる。
- 翻訳の対象は英語から日本語だけとする。
- 翻訳ボタンは、記事の編集モーダルのタイトル欄の右端に、欄と同じ枠の中に置くアイコンのボタンにする。候補の行 (記事の UI) には置かない。アイコンは管理者が用意した `translate.svg` を使う。翻訳中・失敗の表示は、タイトル欄の見出しの行に出す。
- 想定規模は 1 日 1 セット、約 20 記事のうち英語のタイトル約 10 件 (約 300 件/月)。
- 翻訳が必要かの判定と、登録時の自動実行は #105 の範囲で、本仕様には含めない。
