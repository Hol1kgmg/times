# 過去の記事を検索して再掲載の行として足す (issue #171)

## 背景

specs/018 で過去に公開した記事を再掲載できるようになったが、登録済みの URL を貼って保存し、断られた行が再掲載に切り替わる方法しかない。URL を覚えていないと載せ直せない。specs/021 で候補を探す検索ができたので、登録・編集画面から使えるようにする。

## 利用シナリオ

### US1: タイトルか URL の一部から記事を探して再掲載の行にする (P1)

管理者は登録・編集画面で「過去の記事から追加」を開き、タイトルか URL の一部で検索して、出てきた記事を選ぶ。選んだ記事は保存の前から再掲載の行として元のカテゴリの枠に入り、そのまま保存できる。

**受け入れシナリオ**

1. 日付を入れた登録画面で、前の日付の公開の Digest に載った記事をタイトルの一部で検索して選ぶと、その記事が「再掲載 · 〜に初掲載」の行として元のカテゴリの枠に入る。
2. その状態で保存して開き直すと、同じ記事が再掲載の行として並んでいる。
3. 子の記事 (親を持つ記事) を選ぶと、単独の再掲載の行として入る。保存して開き直すと、元の親が呼び出されてその下に並ぶ (specs/018 FR-004)。
4. 検索に当たる記事がないときは、見つからないことが分かる。

### US2: 選べない記事と、その理由が分かる (P1)

管理者は候補の一覧で、この Digest に載せ直せない記事を選べず、なぜ選べないかを読み上げでも知ることができる。

**受け入れシナリオ**

1. 初掲載日が編集中の Digest の日付と同じかそれより後の記事は選べず、「この日より前に公開されていない」ことが分かる。
2. すでにこの Digest の行 (親・子) にある記事は選べず、「もう載っている」ことが分かる。

## 要件

- **FR-001**: 登録・編集画面に「過去の記事から追加」を置き、開いた先でタイトルか URL の一部で検索できる。検索の条件・語の長さ・件数の上限は specs/021 に従う。
- **FR-002**: 日付が入っていない間は「過去の記事から追加」を押せない。選べるかの判定に日付が要るため。
- **FR-003**: 候補ごとにタイトル・URL・カテゴリ・初掲載日を出し、子の記事なら親の記事のタイトルも出す。
- **FR-004**: 初掲載日が編集中の日付以降の記事と、すでにこの Digest に載っている記事は選べない。見た目は小さな印だけにし、理由は読み上げで伝える (frontend-ui-design.md の「選べない理由」)。
- **FR-005**: 選んだ記事は、保存前から再掲載の行として元のカテゴリの枠に入る。行の表示と制限 (「再掲載 · 〜に初掲載」、タイトル・URL・HOT は変えられない、子にできない) は、保存で断られて切り替わった再掲載の行と同じにする (specs/018 FR-008・FR-010)。
- **FR-006**: 子の記事を選んだときも、単独の再掲載の行として足す。
- **FR-007**: 行の数が上限 (100 件) に達しているときは足せない。
- **FR-008**: 足した後に日付を変えて再掲載できなくなった行は、画面では判定し直さず、保存時に断られたときの今の案内 (「再掲載できない記事が含まれてます」) に任せる。
- **FR-009**: 保存の形式と保存時の検証 (specs/018) は変えない。URL を貼って断られた行が再掲載に切り替わる今の流れも残す。

## 成功の基準

- **SC-001**: URL を覚えていなくても、検索 1 回と選択 1 回で過去の記事を再掲載の行にして保存できる。
- **SC-002**: 選べない候補は、すべて理由が読み上げで分かる。
- **SC-003**: URL を貼って再掲載に切り替える既存の流れが今までどおり動く。

## 前提

- 検索は管理者だけが使える (specs/021 FR-001)。登録・編集画面も管理者だけが開ける。
- 選べるかの判定は画面の補助で、最終的な判定は保存時に backend が行う (specs/021 FR-007)。親子の組み合わせなど画面で判定しない食い違いも、保存時の検証に任せる。
- 候補は初掲載日の新しい順に最大 50 件まで出る。それより古い記事は語を絞って探す。

## 対象外

- 再掲載の行の下に、過去の記事を子として検索から足すこと。
- 検索 API・保存 API・保存時の判定の変更。
- 調査用の検索ページの変更。
