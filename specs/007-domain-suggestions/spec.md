# Feature Specification: ドメイン候補

**Feature Branch**: `007-domain-suggestions`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: 管理者向けのドメイン候補 API。記事 (articles) の URL から取り出したドメイン (host) を、登録件数の多い順に返す。検索の補助 (ComboBox などの候補) に使う。入力文字列 q (任意) でドメインを部分一致で絞り込み、limit (1〜50、既定 20) 件まで返す。返り値は host と件数。管理者専用 (bearerAuth)、Digest のステータスを問わず全記事を対象にする。domains テーブル・ドメインの正規化 (youtu.be と youtube.com の統合、www.)・UI 部品 (ComboBox) は範囲外。

**追加 (2026-11-03)**: 公開状態の Digest の記事のドメインだけを数える経路も作る。今後一般ユーザーのアカウントを足したとき、管理者以外のログインユーザーも使う想定なので、全件の経路とは別のエンドポイントにする。使えるのはログインユーザーだけ (今ログインできるのは管理者だけ)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登録済みのドメインを件数順に一覧する (Priority: P1)

管理者は、これまでに登録した記事がどのサイトから来ているかを知りたい。入力なしで候補を求めると、登録済みの記事のドメインが、記事の件数の多い順に、件数と一緒に返る。

**Why this priority**: 「どんなドメインが登録されているか」をアプリの中から見る手段がまだない。これだけで一覧として使える。

**Independent Test**: speakerdeck.com の記事 3 件、zenn.dev の記事 1 件を登録した状態で候補を求め、`speakerdeck.com (3)` → `zenn.dev (1)` の順で返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数のドメインの記事が登録されている, **When** 入力なしで候補を求める, **Then** ドメインごとに 1 行、記事の件数の多い順で返る
2. **Given** 件数が同じドメインが複数ある, **When** 候補を求める, **Then** それらはドメイン名の順で並ぶ (毎回同じ順になる)
3. **Given** 下書き・公開・非公開の Digest に記事がある, **When** 候補を求める, **Then** ステータスを問わずすべての記事が件数に入る
4. **Given** 記事が 1 件もない, **When** 候補を求める, **Then** 空の一覧が返る

---

### User Story 2 - 入力した文字でドメインを絞り込む (Priority: P1)

管理者は、検索欄に「zen」と打つと、候補が `zenn.dev` のように、その文字を含むドメインだけに絞られる。候補の数は上限で切られ、入力のたびに軽く返る。

**Why this priority**: 検索欄の候補として使うのがこの機能の目的。絞り込めなければ候補として使えない。

**Independent Test**: zenn.dev と qiita.com の記事がある状態で「ZEN」を入力として候補を求め、zenn.dev だけが返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** zenn.dev と qiita.com の記事がある, **When** 「zen」で候補を求める, **Then** zenn.dev だけが返る
2. **Given** 同上, **When** 「ZEN」で候補を求める, **Then** 大文字小文字を区別せず zenn.dev が返る
3. **Given** 25 種類のドメインがある, **When** 件数の指定なしで候補を求める, **Then** 上位 20 件だけが返る
4. **Given** 同上, **When** 件数を 5 と指定する, **Then** 上位 5 件だけが返る
5. **Given** 一致するドメインがない, **When** 候補を求める, **Then** 空の一覧が返る (エラーにしない)

---

### User Story 3 - 全件の候補は管理者以外に見せない (Priority: P1)

ステータスを問わない全件の候補は管理者のためのもので、ログインしていない人には返さない。

**Why this priority**: 下書き・非公開の Digest の記事も数えるため、公開すると未公開の内容 (どのサイトを載せる予定か) が漏れる。

**Independent Test**: ログインせずに候補を求め、拒否されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログインしていない, **When** 候補を求める, **Then** 認証が必要として拒否される
2. **Given** 管理者としてログインしている, **When** 候補を求める, **Then** 一覧が返る

---

### User Story 4 - 公開の記事のドメインだけを、ログインユーザーが絞り込む (Priority: P2)

ログインしているユーザーは、公開の Digest に載った記事のドメインだけを候補として求められる。下書き・非公開の Digest の記事は件数に入らず、それらにしかないドメインは候補に出ない。絞り込みと件数の上限は US2 と同じ。今ログインできるのは管理者だけだが、一般ユーザーのアカウントができたらその人たちも使う。

**Why this priority**: 管理者以外にも出せる範囲の候補を、全件の経路と分けて先に用意しておく。今の利用者は管理者だけなので、全件の候補 (US1〜3) より後でよい。

**Independent Test**: 公開の Digest に zenn.dev の記事 1 件、下書きの Digest に zenn.dev の記事 2 件と example.com の記事 1 件がある状態で公開分の候補を求め、`zenn.dev (1)` だけが返ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 公開・下書き・非公開の Digest に記事がある, **When** 公開分の候補を求める, **Then** 公開の Digest の記事だけが件数に入る
2. **Given** 下書きの Digest にしかないドメインがある, **When** 公開分の候補を求める, **Then** そのドメインは出ない
3. **Given** 同上, **When** 全件の候補 (US1) を求める, **Then** そのドメインは出る
4. **Given** ログインしていない, **When** 公開分の候補を求める, **Then** 認証が必要として拒否される
5. **Given** ログインしている, **When** 入力文字列と件数を指定して公開分の候補を求める, **Then** US2 と同じ規則で絞り込まれ、切られる
6. **Given** 公開の Digest を非公開にした, **When** 公開分の候補を求める, **Then** その Digest の記事は件数から外れている

### Edge Cases

- 入力に `%` や `_` が含まれる: 特別な意味を持たない文字として扱い、文字どおりに含むドメインだけを返す
- 入力が空文字: 入力なしと同じに扱う
- 入力が長すぎる (100 文字超): 不正な入力として拒否する
- 件数の指定が 1 未満・50 超・数値でない: 不正な入力として拒否する
- URL にポート番号が付いている (`example.com:8080`): ポートを除いたドメインで数える
- `youtu.be` と `youtube.com`、`www.example.com` と `example.com`: 別のドメインとして数える (正規化は範囲外)
- 大文字を含むドメインの URL: そのまま別のドメインとして扱う (登録時の URL をそのまま使う)
- 公開の Digest が 1 件もない: 公開分の候補は空の一覧を返す

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、登録済みの記事の URL からドメイン (スキームの後ろからパス・ポートの手前まで) を取り出し、ドメインごとの記事の件数を返さなければならない
- **FR-002**: 結果は件数の多い順、同数ならドメイン名の昇順で並べなければならない
- **FR-003**: 入力文字列が与えられたら、それを含むドメインだけに絞らなければならない。比較は大文字小文字を区別せず、入力中の記号は文字どおりに扱う
- **FR-004**: 返す件数の上限を 1〜50 で指定でき、指定がなければ 20 件としなければならない。範囲外は不正な入力として拒否する
- **FR-005**: 入力文字列は 100 文字までとし、超えたら不正な入力として拒否しなければならない
- **FR-006**: 全件の候補は、Digest のステータス (下書き・公開・非公開) を問わず、すべての記事を数えなければならない
- **FR-007**: 全件の候補は、管理者としてログインしている場合にだけ返し、それ以外は認証が必要として拒否しなければならない
- **FR-008**: 記事の子記事 (関連記事) も 1 件の記事として数えなければならない
- **FR-009**: ドメインを別に保存せず、記事の URL から毎回求めなければならない (記事の追加・編集・削除がすぐ反映される)
- **FR-010**: 全件の候補とは別の経路で、公開の Digest の記事だけを数えた候補を返さなければならない。FR-001〜005・008・009 は同じに適用する
- **FR-011**: 公開分の候補は、ログインしている場合にだけ返し、それ以外は認証が必要として拒否しなければならない。管理者に限らない (今ログインできるのは管理者だけ)

### Key Entities

- **ドメイン候補**: 記事の URL から求めた値。ドメイン名と、そのドメインの記事の件数を持つ。保存はしない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理者は、登録済みの記事のドメインと件数の一覧を、データベースを直接見ずに 1 回の操作で得られる
- **SC-002**: 記事を登録・編集した直後に候補を求めると、その変更が件数に反映されている
- **SC-003**: 現在の記事数 (数十〜数百件) で、入力のたびの候補が体感で待たずに返る (1 秒未満)
- **SC-004**: ログインしていない状態で候補を求めた場合、全件・公開分とも 100% 拒否される
- **SC-005**: 公開分の候補に、下書き・非公開の Digest にしかないドメインが 1 件も出ない

## Assumptions

- 利用者は管理者 1 人。複数の管理者の記事を分けて数えることはしない
- 一般ユーザーのアカウントは後続の機能で作る。そのとき、全件の候補には管理者かどうかの判定を足す (今はログイン = 管理者なので、ログインの確認だけで FR-007 を満たす)
- 記事の URL は `http://` か `https://` で始まることが登録時に保証されている (既存の制約)
- 記事数は当面数百件程度で、記事の URL を毎回数えても応答時間に問題は出ない
- この機能はデータを返す部分だけを作る。候補を出す検索欄 (UI 部品) と、それを置く画面は後続の機能で作る
- ドメインの正規化 (短縮 URL の統合、`www.` の除去、サブドメインの集約)、ドメインごとの属性の保存は範囲外
