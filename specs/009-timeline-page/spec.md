# Feature Specification: Digest のタイムライン画面

**Feature Branch**: `009-timeline-page`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: Digest のタイムライン画面 (specs/008 の API とサーバー関数を使う画面)。パス `/timeline`、サイドバーのタブ `#timeline` はログイン中だけ `#general` の下に出す。未ログインには画面がないものとして扱う。公開の Digest を古い順 (最新がいちばん下) に、トップと同じ投稿の見た目で連ねるチャットログ。初回表示は一番下までスクロールする。上端までスクロールしたら、いちばん古い日付より前の次の 7 件を自動で読み足して上に差し込む (見ている位置は動かさない、読み込みは重ねない、7 件未満で終わり、中身が画面より短ければ埋まるまで続けて読む)。読み込み中は上端に「読み込み中」、失敗したら「読み込めませんでした」と再試行ボタン。0 件は「まだ記事がないです」。記事のプレビューはホバーで出す。Markdown のコピーボタンは置かない。e2e は 1 本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直近の Digest をチャットログとして読む (Priority: P1)

ログインしているユーザーがサイドバーの `#timeline` を開くと、公開の Digest がトップと同じ投稿の見た目で、古いものが上・最新がいちばん下の順に並ぶ。開いた時点で一番下 (最新) が見えている。

**Why this priority**: タイムラインの最初の表示。これがないと画面として成り立たない。

**Independent Test**: 公開の Digest が 2 件以上ある状態でログインして `#timeline` を開き、日付が上から古い順に並び、最新の Digest が画面に見えていることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログインしていて公開の Digest が複数ある, **When** サイドバーの `#timeline` を押す, **Then** `/timeline` に移り、直近の Digest (最大 7 件) が上から古い順に並ぶ
2. **Given** タイムラインを開いた, **When** 表示が終わる, **Then** いちばん下の最新の Digest が見える位置までスクロールされている
3. **Given** 並んだ投稿, **When** 見た目を見る, **Then** 各投稿はトップの投稿と同じ形 (日付の区切り・件数・`z_times.dev`・カテゴリごとの記事・ホットの印・関連記事) で、Markdown のコピーボタンはない
4. **Given** PC で記事にカーソルを合わせる, **When** 少し待つ, **Then** トップと同じく記事のプレビューが出る (最新の日以外の記事でも出る)
5. **Given** 公開の Digest が 1 件もない, **When** 開く, **Then** 「まだ記事がないです」と出る

---

### User Story 2 - 上へさかのぼると自動で古い Digest が足される (Priority: P1)

ユーザーがタイムラインを上端までスクロールすると、いま表示しているいちばん古い日付より前の Digest が自動で読み込まれ、上に足される。読んでいた位置は動かない。これを繰り返して最初の Digest までたどれる。

**Why this priority**: 過去をたどれることがこの画面の目的。直近だけならトップで足りる。

**Independent Test**: 公開の Digest が 8 件以上ある状態で開き、上端までスクロールすると、それより古い Digest が上に足され、見ていた投稿が画面上の同じ位置に残ることを確認できる。

**Acceptance Scenarios**:

1. **Given** まだ古い Digest がある, **When** 上端までスクロールする, **Then** 上端に「読み込み中」が出たあと、次の古い Digest (最大 7 件) が古い順で上に足される
2. **Given** 古い Digest が足された, **When** 足し終わる, **Then** 足す前に見ていた投稿は画面上の同じ位置に見えたまま (勝手に飛ばない)
3. **Given** 読み込みの途中, **When** さらに上端でスクロールする, **Then** 読み込みを重ねて始めない (同じ Digest が二重に並ばない)
4. **Given** 最後に読み込めた件数が 7 件未満, **When** さらに上端までスクロールする, **Then** それ以上は読み込まない
5. **Given** 画面が高く、並んだ投稿が画面の高さに満たない, **When** 開く, **Then** 画面が埋まるか最初の Digest に届くまで、続けて自動で読み込む
6. **Given** 最後までたどった, **When** 並びを見る, **Then** 公開の Digest がすべて 1 回ずつ、古い順に並ぶ

---

### User Story 3 - 読み込みに失敗したらやり直せる (Priority: P2)

古い Digest の読み込みに失敗すると、上端に「読み込めませんでした」と再試行のボタンが出て、押すとやり直せる。

**Why this priority**: 失敗は稀で、再読み込みでも回復できる。ただし失敗のたびに読み込みを繰り返したり、黙って止まったりしないようにする。

**Independent Test**: 通信を止めた状態で上端までスクロールし、「読み込めませんでした」と再試行ボタンが出ること、通信を戻して押すと古い Digest が足されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 古い Digest の読み込みが失敗した, **When** 上端を見る, **Then** 「読み込めませんでした」と再試行ボタンが出て、すでに並んでいる投稿は消えない
2. **Given** 失敗の表示が出ている, **When** 上端でスクロールし続ける, **Then** 自動では読み込みをやり直さない
3. **Given** 失敗の表示が出ている, **When** 再試行ボタンを押す, **Then** 同じ続きをもう一度読み込み、成功すれば上に足される

---

### User Story 4 - ログインしていない人には出さない (Priority: P1)

タイムラインはログインしているユーザーのための画面で、ログインしていない人にはタブも画面も出さない。

**Why this priority**: 過去の Digest をまとめて見せる範囲をログインユーザーに限るため (specs/008)。

**Independent Test**: ログインせずに `/timeline` を開くと見つからない画面になり、サイドバーに `#timeline` がないことを確認できる。

**Acceptance Scenarios**:

1. **Given** ログインしていない, **When** サイドバーを見る, **Then** `#timeline` はなく `#general` だけがある
2. **Given** ログインしていない, **When** `/timeline` を直接開く, **Then** 見つからない画面になる
3. **Given** ログインしている, **When** サイドバーを見る, **Then** `#general` の下に `#timeline` があり、タイムラインを開いている間は選択中の見た目になる

### Edge Cases

- 公開の Digest がちょうど 7 件: 最初の表示で 7 件並び、上端で 1 回読み込んで空が返り、そこで終わる
- 読み込み中に別の画面へ移った: 戻ってきたときは最初の表示からやり直す (読み足した分は保たない)
- 読み込み中・失敗の表示が出たり消えたりしても、並んだ投稿の位置は動かない (表示の高さを普段から取っておく)
- 読み込み中にキーボードで投稿のリンクへ移る: 操作は妨げない
- 動きを減らす設定: スクロールの補正に動きは付けない (位置は瞬時に合わせる)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは `/timeline` に、ログインしているユーザーだけが開けるタイムライン画面を出さなければならない。ログインしていない場合は見つからない画面にする
- **FR-002**: サイドバー (狭い画面ではヘッダーのメニュー) に、ログイン中だけ `#general` の下に `#timeline` を出さなければならない
- **FR-003**: 公開の Digest を、古いものが上・最新がいちばん下の順に、トップの投稿と同じ見た目で並べなければならない。Markdown のコピーボタンは置かない
- **FR-004**: 開いたときに、最新の Digest が見える一番下の位置を表示しなければならない
- **FR-005**: 上端までスクロールしたら、表示中のいちばん古い日付より前の Digest を最大 7 件、自動で読み込み、上に足さなければならない
- **FR-006**: 古い Digest を足しても、足す前に見ていた内容の画面上の位置を変えてはならない
- **FR-007**: 読み込み中に次の読み込みを始めてはならない。最後に読み込めた件数が 7 件未満なら、それ以上読み込んではならない
- **FR-008**: 並んだ投稿が画面の高さに満たない間は、画面が埋まるか古い Digest がなくなるまで続けて読み込まなければならない
- **FR-009**: 読み込み中は上端に「読み込み中」を、失敗したら「読み込めませんでした」と再試行ボタンを出さなければならない。失敗の後は再試行ボタンが押されるまで自動で読み込まない
- **FR-010**: 公開の Digest が 1 件もなければ「まだ記事がないです」と出さなければならない
- **FR-011**: PC では、トップと同じく記事にカーソルを合わせるとプレビューを出さなければならない。どの日の記事でも出す

### Key Entities

- **Digest**: 1 日付分の記事のまとまり (既存)。タイムラインには公開のものだけが並ぶ
- **タイムラインの表示**: 古い順に並んだ Digest の列と、まだ古いものがあるか・読み込み中か・失敗したかの状態

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログインユーザーは、サイドバーから 1 回押すだけで直近 7 日分の Digest をチャットログとして読める
- **SC-002**: 上へスクロールし続けるだけで、ボタンを押さずに公開の Digest をすべて、重複も抜けもなくたどれる
- **SC-003**: 古い Digest が足されたとき、読んでいた投稿が画面上で動かない (目で見て飛ばない)
- **SC-004**: ログインしていない人が、タイムラインの画面やタブを目にすることは 0 回
- **SC-005**: 読み込みに失敗しても、すでに読んだ投稿が失われず、1 回の操作でやり直せる

## Assumptions

- データの取得は specs/008 の公開の Digest の一覧 (新しい順、日付より前を指定して続きを読む、件数は 7) をそのまま使い、画面の側で古い順に並べ替える。新しい API は作らない
- 「ログインしている」は今は管理者と同じ。一般ユーザーができたら、画面の入口とプレビューの取得も一般ユーザー向けに広げる (specs/008 と同じ扱い)
- 記事のプレビューは、ログインしている人に限って任意の記事の URL から取得する。トップのプレビューは最新の日の記事に限っているので、タイムラインでは使えない
- 読み足した分は画面を離れると捨てる。戻ってきたときのスクロール位置や読み足した範囲は覚えない
- 新しく公開された Digest を開いたまま自動で下に足すこと (リアルタイムの更新) はしない。開き直せば出る
- トップの `#general` 見出しをタイムラインへのリンクにすることは、この機能では行わない
- 自動テストの e2e は 1 本だけで、ログイン状態で開くと公開の Digest が古い順に並び最新が一番下にあることを確かめる。読み足しは e2e 用のデータ量に左右されるので e2e では押さえず、手動で確認する
