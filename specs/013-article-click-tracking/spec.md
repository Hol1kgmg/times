# Feature Specification: 記事リンクのクリック数を記事ごとに数える

**Feature Branch**: `013-article-click-tracking`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: issue #109「記事リンクのクリック数を GA4 で計測する」。Digest の記事リンクが押された回数を記事ごとに数え、GA4 の画面で記事ごとの回数を見られるところまでにする。PC・モバイルの両方で計測し、リンクの href は記事の URL のまま、広告ブロッカーにできるだけ止められず、編集画面のプレビューのクリックは数えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 読み手が記事リンクを押すと 1 回として数えられる (Priority: P1)

読み手がトップやタイムラインで Digest の記事リンクを押す (PC のクリック、モバイルのタップ、中クリック) と、記事は普段どおり新しいタブで開き、その裏でシステムが「どの記事が、どの日の Digest で押されたか」を 1 回分の記録として集計先に届ける。読み手の操作や記事の開き方は何も変わらない。

**Why this priority**: 押された回数が溜まらなければ、記事ごとの反応を見るという目的が成り立たない。

**Independent Test**: トップの記事リンクを PC とモバイル幅でそれぞれ押し、記事が新しいタブで開くことと、集計先にその記事の 1 回分の記録が届くことを確認できる。

**Acceptance Scenarios**:

1. **Given** トップに最新の Digest が出ている, **When** 読み手が記事リンクをクリックする, **Then** 記事が新しいタブで開き、その記事の識別子・URL・Digest の日付を持つ記録が集計先に 1 件届く
2. **Given** モバイルの画面, **When** 記事リンクをタップする, **Then** PC と同じ形の記録が 1 件届く
3. **Given** PC の画面, **When** 記事リンクを中クリックする, **Then** 記録が 1 件届く
4. **Given** タイムラインの過去の Digest, **When** 記事リンクを押す, **Then** その Digest の日付を持つ記録が届く
5. **Given** 広告ブロッカー (uBlock Origin の既定のフィルタ) を有効にしたブラウザ, **When** 記事リンクを押す, **Then** 記録が届く
6. **Given** 子記事のリンク, **When** 押す, **Then** 親の記事とは別の記事として記録が届く

---

### User Story 2 - 記事の URL をそのままコピーできる (Priority: P1)

読み手が記事リンクを右クリックや長押しして「リンクをコピー」すると、記事そのものの URL が取れる。計測のために中継の URL に置き換わらない。

**Why this priority**: 記事を人に共有する手段を計測のために壊さないことが、計測を入れる前提。

**Independent Test**: 記事リンクを右クリックしてリンクのアドレスをコピーし、記事の元の URL と一致することを確認できる。

**Acceptance Scenarios**:

1. **Given** 公開画面の記事リンク, **When** 右クリック (モバイルでは長押し) からリンクをコピーする, **Then** 記事の元の URL が取れる

---

### User Story 3 - 管理者が記事ごとのクリック数を見る (Priority: P1)

管理者が集計先 (GA4) の画面を開くと、記事ごとに押された回数を一覧で見られる。何の記事かは URL で分かり、どの日の Digest で押されたかでも分けられる。

**Why this priority**: 届いた記録を記事ごとに読めなければ、数えた意味がない。

**Independent Test**: 記事を何件か押したあと、GA4 の探索で記事の URL ごとのイベント数を出し、押した回数と合うことを確認できる。

**Acceptance Scenarios**:

1. **Given** 記事が何回か押された, **When** 管理者が GA4 で記事のクリックに絞り、記事の URL ごとに回数を出す, **Then** 押された回数が記事ごとに出る
2. **Given** 同じ記事を含む Digest を編集して保存した, **When** 保存の前後で同じ記事が押される, **Then** 同じ記事の識別子で数えられる
3. **Given** URL を直した記事, **When** 直した後に押される, **Then** 直す前とは別の記事として数えられる

---

### User Story 4 - 編集のプレビューは数えない (Priority: P2)

管理者が登録・編集画面のプレビューで記事リンクを押しても、記録は送られない。

**Why this priority**: 管理者が確認のために押した回数が混ざると、読み手の反応が読めなくなる。ただし公開画面のクリックほど件数は多くない。

**Independent Test**: 編集画面のプレビューで記事リンクを押し、記録が送られないことを確認できる。

**Acceptance Scenarios**:

1. **Given** 編集画面のプレビュー, **When** 記事リンクを押す, **Then** 記録は送られない
2. **Given** まだ保存していない下書きの記事 (識別子を持たない), **When** プレビューで押す, **Then** 記録は送られない

---

### Edge Cases

- 記録の送信が失敗した: 記事は普段どおり開き、再送はしない。読み手にエラーは出さない。
- 形の合わない記録 (識別子・URL・日付の欠け、形式の誤り) が受付に届いた: 集計先に送らない。
- bot (User-Agent で bot と分かるもの) からの記録: 集計先に送らない。
- 管理者がログインしたまま公開画面で押した: 読み手と同じく数える。
- 右クリック・長押しのメニューから「新しいタブで開く」: 数えない (許容する)。
- ページの準備が終わる前 (画面が出てから操作できるようになるまで) のクリック: 数えない (許容する)。
- RSS リーダーから開いた記事: サイトの外で開かれるので数えない (許容する)。
- 同じ読み手が同じ記事を何度も押した: 押した回数だけ数える。ユニーク数は数えない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、公開画面 (トップ・タイムライン) の記事リンクのクリック・タップ・中クリックごとに、記事の識別子・記事の URL・Digest の日付を持つ記録を 1 件送らなければならない (MUST)。
- **FR-002**: 記事リンクの行き先は記事の元の URL のままにし、計測のための中継の URL に置き換えてはならない (MUST NOT)。
- **FR-003**: 記録の送信で、記事の開き方 (新しいタブで開く) を遅らせたり妨げたりしてはならない (MUST NOT)。送信の失敗は読み手に示さず、再送しない。
- **FR-004**: ブラウザから集計先 (GA4) へ直接送ってはならない (MUST NOT)。記録はサイト自身の受付に送り、受付が集計先へ転送する。
- **FR-005**: 受付の場所には、計測らしい名前 (track / collect / analytics / beacon など) を使ってはならない (MUST NOT)。
- **FR-006**: 受付は記録の形を検証し、形の合わない記録を集計先に送ってはならない (MUST NOT)。
- **FR-007**: 受付は User-Agent で bot と分かる記録を集計先に送ってはならない (MUST NOT)。
- **FR-008**: 集計先の認証情報 (測定 ID・API secret) をブラウザに渡してはならない (MUST NOT)。
- **FR-009**: 編集画面のプレビューの記事リンクからは記録を送ってはならない (MUST NOT)。識別子を持たない下書きの記事は、記録を送れない形にする。
- **FR-010**: 記事の識別子には保存済みの記事の id を使わなければならない (MUST)。保存で id が変わらないこと (#114) に頼り、URL を直した記事は別の記事として数える。
- **FR-011**: 記録は読み手を識別してはならない (MUST NOT)。読み手を区別する値は記録ごとに使い捨てにし、Cookie などで持ち回らない。セッションの情報も載せない。
- **FR-012**: 管理者は集計先の画面で、記事の識別子・記事の URL・Digest の日付ごとにクリック数を出せなければならない (MUST)。

### Key Entities

- **記事のクリック**: 公開画面で記事リンクが 1 回押されたことの記録。記事の識別子 (保存済みの記事の id)、記事の URL、Digest の日付を持つ。読み手は識別しない。
- **記事**: 既存の Digest の記事。保存で id が変わらない (#114)。URL を直すと別の記事になる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: PC とモバイルの公開画面で記事リンクを押したとき、通信が成功した押下の 100% が集計先に記録として届く。
- **SC-002**: 広告ブロッカー (uBlock Origin の既定のフィルタ) を有効にした状態でも、記事リンクの押下が集計先に届く。
- **SC-003**: 編集画面のプレビューでの押下が集計先に届く件数が 0 件である。
- **SC-004**: 公開画面の記事リンクの行き先のうち、記事の元の URL と異なるものが 0 件である。
- **SC-005**: 管理者が集計先の画面で、記事ごとのクリック数を 1 つの表として出せる。
- **SC-006**: 記録の送信を入れる前後で、記事リンクを押してから記事のタブが開くまでの時間が読み手に分かるほど変わらない。

## Assumptions

- 集計先は GA4 とし、受付 (Cloudflare Workers) から GA4 の Measurement Protocol で転送する。イベント名は `article_click`、パラメータは `article_id` / `article_url` / `digest_date` (issue #109 のとおり)。
- `article_id` / `article_url` / `digest_date` は、デプロイの前に GA4 でイベントスコープのカスタムディメンションとして登録しておく。登録より前のイベントは集計されないため。登録は管理者がコンソールで行い、本機能の実装には含めない。
- 端末・地域 (`user_agent` / `ip_override` / `device` / `user_location` など) を Measurement Protocol でどこまで載せられるかは plan で公式ドキュメントを確かめる。載せられるものは受付で付け、載せられなければ端末・地域の内訳はなしにする。
- ブラウザからの送信は、ページが残る (リンクは新しいタブで開く) 前提で、ブロッカーの種類別のルールに当たりにくい方式を plan で選ぶ (issue #109 では `fetch` + `keepalive`)。
- 公開画面は SSR なので、操作できるようになる前のクリックは数えない。右クリック・長押しのメニューから開いた記事、RSS から開いた記事も数えない。
- ユニーク数・セッション単位の集計は出さない。GA4 の「ユーザー数」は意味を持たない。
- 管理者自身の公開画面でのクリックは数える。除外は件数が増えてから検討する。
- 集計結果を管理画面に出すこと、BigQuery へのエクスポート、自前の DB への保存、RSS からのクリックの計測は本仕様に含めない。
