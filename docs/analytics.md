# アクセス指標 (GA4)

閲覧と記事のクリックを GA4 で数え、記事別 UU・サイト UU・DAU・MAU を出す。経緯と判断は specs/013 (記事のクリック) と specs/014 (匿名 ID・閲覧・集計)。

## 指標

| 指標 | 定義 |
|---|---|
| 記事クリック数 | `article_click` の件数 |
| 記事別 UU | 期間内にその記事を押した異なる匿名 ID の数 |
| サイト UU | 期間内に `page_view` を持つ異なる匿名 ID の数 |
| DAU | 日ごとのサイト UU |
| MAU | 過去 30 日のサイト UU。暦の月ではない |

- 匿名 ID はブラウザ単位で、実人数ではない。同じ人の PC とスマホは 2 人、サイトのデータを消すと別の人になる。
- 1 人が複数の記事を押すので、記事別 UU を足してもサイト UU にならない。サイト UU は `page_view` で数える。

## 送っているもの

ブラウザ → `POST /open` (Workers) → GA4 Measurement Protocol。ブラウザから GA4 へ直接は送らない。契約は specs/014 `contracts/open.md`。

| イベント | いつ | params |
|---|---|---|
| `page_view` | 公開画面 (`/`・`/timeline`) を開く・移るたび。管理画面とログイン画面は送らない。通知のリンク先 `/digest/$date` はすぐトップへ移るので、トップの分だけ数える | `page_location` (クエリ・フラグメントなし)、`page_title` |
| `article_click` | トップ・タイムラインの記事リンクのクリック・タップ・中クリック。プレビューは送らない | `article_id`、`article_url` (先頭 100 文字)、`digest_date` |

- どちらも `client_id` = 匿名 ID (localStorage `times.cid` の UUID。保存できないブラウザではページの中だけの ID)、`engagement_time_msec: 1`、`ip_override` (地域)、`device.category` を付ける。`session_id` は付けない。
- 読み手への告知はトップの FAQ「何か記録してる？」。

## GA4 での出し方

すべて探索 (自由形式) で出す。標準レポートはアクティブユーザーが基準で、イベントで絞れないため。

| 指標 | 行 | 値 | フィルタ | 期間 |
|---|---|---|---|---|
| 記事クリック数・記事別 UU | `article_id`、`article_url` | イベント数、総ユーザー数 | イベント名 = `article_click` | 任意 |
| サイト UU | なし | 総ユーザー数 | イベント名 = `page_view` | 任意 |
| DAU | 日付 | 総ユーザー数 | イベント名 = `page_view` | 任意 |
| MAU | なし | 総ユーザー数 | イベント名 = `page_view` | 過去 30 日間 |

### 総ユーザー数とアクティブユーザー数

- **総ユーザー数**: 期間内にイベントを 1 件でも記録した異なるユーザーの数。UU はこちらで読む。
- **アクティブユーザー数**: エンゲージメントのあったユーザーの数。GA4 の標準レポートの「ユーザー」はこちら。Measurement Protocol だけで送ると `engagement_time_msec` / `session_id` の有無で値が変わるので、指標にしない。
- GA4 標準の「28 日間のアクティブ ユーザー数」は 28 日・アクティブユーザー基準なので、MAU には使わない。

### 前提の設定

| 設定 | 値 | 理由 |
|---|---|---|
| レポート用識別子 | 既定 (ハイブリッド) かデバイスベース | User-ID を送らずシグナルも使わないので、どちらでも匿名 ID だけで数える |
| Google シグナル | 無効 | 有効だとユーザー指標にしきい値がかかり、少ない数が隠れる |
| データ保持期間 | 14 か月 (2026-11-10 に 2 か月から変更) | 探索で出せるのは保持期間の分だけ。変更より前のデータは延長されない |
| タイムゾーン | 日本 (Asia/Tokyo) | 日付の境目になる |

## 読むときの注意

- **日付の境目**: プロパティのタイムゾーン (日本) の 0 時で切る。記録が受付に届いた時点の日付で数える。
- **保持期間**: 探索で出せるのは保持期間の分だけ。標準レポートの集計値は消えない。
- **bot**: 受付で User-Agent に `bot|crawl|spider|headless` を含むものを除く。GA4 の既知の bot 除外が Measurement Protocol の送信にも効くかは明記されていない。
- **欠測**: JavaScript が動かない環境、ページが操作できるようになる前の操作、`keepalive` の送信失敗 (再送しない)、RSS から直接開いた記事、右クリック・長押しから開いた記事。specs/014 のデプロイより前から開いていたタブは古い形式で送るので受付が断る。
- **水増し**: Safari は、サイトを 7 日開かないとスクリプトが書いた保存を消す (ITP)。たまにしか来ない Safari の読み手は戻るたびに新しい人になり、MAU が多めに出る。管理者自身の閲覧・クリックも数える。

## GA4 で足りないときの代わり

| 方法 | 効くこと | 要るもの | 選ぶ条件 |
|---|---|---|---|
| BigQuery Export | `user_pseudo_id` (= 匿名 ID) を `COUNT(DISTINCT)` で数え、しきい値・モデリングがかからない | BigQuery のプロジェクトと GA4 のリンク | 実測で総ユーザー数が合わないとき、まずこれ |
| 受付で保存する | Workers から D1 か backend の DB にイベントを残し、自前で集計する | 保存期間・削除・集計の画面まで自前 | サイトの画面に指標を出したくなったとき |
| 匿名 ID を Cookie で配る | ITP による水増しを減らす (サーバーが付けた Cookie は消されにくい) | `Set-Cookie` と告知の書き直し | Safari の水増しが目立つとき |

## 実測の結果

| 指標 | 期待 | 結果 |
|---|---|---|
| 記事 X のイベント数 | 3 | 未実施 |
| 記事 X の総ユーザー数 | 2 | 未実施 |

| その日のアクティブ ユーザー数 | 記録するだけ | 未実施 |
| デバイス カテゴリ | mobile / desktop が分かれる | 未実施 |
